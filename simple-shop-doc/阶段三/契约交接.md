# Simple-Shop 阶段三 · 契约交接（C2）

> **文档性质**：阶段三后端对外契约的交接说明，供买家端、卖家端与 E2E 使用。
> **适用范围**：`simple-shop-backend` 的 REST 接口与 `/media` 静态资源。
> **权威来源**：字段级定义以同目录 `openapi.json` 为准；码表以 `ErrorCode` 枚举为准；本文补充 OpenAPI 表达不了的边界与口径。
> **不负责**：前端 `api/types.ts`、错误码中文文案、页面交互——由前端阶段各自维护。
> **快照版本**：OpenAPI `info.version = 1.0.0`（阶段三交付快照，38 条路径）。
> **日期**：2026-11-10

---

## 1. 怎么用

- `openapi.json` 可直接导入 Swagger UI、Postman、Apifox；后端本地启动后也可实时访问 `/v3/api-docs`。
- 生产环境用 `SPRINGDOC_ENABLED=false` 关闭文档端点，快照以本目录文件为准。
- 字段名、枚举值、分页结构以 `openapi.json` 为准；行为边界、状态口径、错误码含义以本文为准。
- 本文与后端 README 描述同一套接口，如出现不一致，以代码与 `openapi.json` 为准并回修文档。

## 2. 全局约定

| 项 | 约定 |
| --- | --- |
| 基地址 | 同源；前端开发期由 Vite 代理 `/api`、`/media` 到 `http://localhost:8080` |
| 响应外壳 | `{code, message, data}`；`code=0` 成功；参数校验失败额外带 `errors:[{field,message}]` |
| 业务拒绝 | 默认 HTTP 200 + 非零业务码；401 / 400 / 404 / 500 才使用 HTTP 状态码（见第 5 节） |
| 认证 | `Authorization: Bearer <token>`；买家与卖家令牌不能互用；默认会话 30 分钟；后端重启会丢会话 |
| 字段命名 | 全部 snake_case，前端不得转驼峰 |
| 分页 | 请求 `page` 从 1 起、`page_size` 默认 10、上限 100；响应 `{items, page, page_size, total}` |
| 时间 | 库内、接口、日志统一 UTC；响应为 ISO-8601 秒级字符串，带 `Z` |
| 金额 | 两位小数；总额与小计由服务端计算，前端不要自行相乘累加 |
| 媒体 | 图片/视频上传后返回相对 URL，直接以 `/media/**` 访问；商品图 5MB、描述视频 20MB，multipart 请求上限 25MB |
| 限流 | 总开关 `simple-shop.rate-limit.enabled`；注册、登录各 50 次/分钟（登录按「账号 + IP」）；提交订单 1000 次/分钟兜底、按买家计；购物车与收藏不限流 |

**E2E / 压测环境必须整体关闭限流**（yml 开关），不要靠调大阈值绕过。

## 4. 关键数据结构

### 4.1 订单

**订单头 `OrderData`**（列表项与详情共用）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `order_id` | string | 订单主键（UUID 前缀 O），详情与订单项都用它 |
| `order_no` | string | 人类可读订单号，`SO + yyyyMMdd(UTC) + 6 位每日序列` |
| `status` | string | 六个状态之一，见 6.2 |
| `total_amount` | number | 订单总额，两位小数 |
| `item_count` | int | 明细行数（不是件数合计） |
| `create_at` / `update_at` | string | 下单时间 / 最后状态变更时间 |
| `buyer` | object | `{id, username}`；用户名实时读账号，不是快照 |

**下单返回 `OrderPlacedData`**：`order_id`、`order_no`、`total_amount`、`status`、`create_at`。
**状态变更返回 `OrderStatusData`**：`order_id`、`order_no`、`status`、`update_at`。

**订单项 `OrderItemData`**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `goods_id` | string | 商品引用 |
| `goods_name` | string | 下单时名称快照 |
| `unit_price` | number | 下单时单价快照 |
| `quantity` | int | 数量 |
| `amount` | number | 小计 = 单价 × 数量，服务端算 |

**下单请求**：`{items:[{goods_id, quantity}]}`；不接收金额，不接收买家 ID（取令牌主体）。

### 4.2 购物车

**`CartItemData`**：`goods_id`、`name`、`price`、`stock`、`status`、`off_shelf_reason`、`main_image_url`、`selectable`、`added_at`。

- `selectable` = 商品在售；由商品状态派生，不落库。**在售但库存为 0 仍为 `true`**，缺货到结算时拦截。
- 购物车**不存数量与勾选**，后端也没有这两个字段；由前端 `localStorage` 维护。
- 列表**不分页**：`{items:[...]}`。

### 4.3 收藏

**`FavoriteItemData`**：`goods_id`、`name`、`price`、`stock`、`status`、`off_shelf_reason`、`main_image_url`、`detail_available`、`favorited_at`。

- `detail_available` = 商品在售；已下架行保留展示，但前端不提供详情跳转。
- 收藏列表**分页**（默认 10、上限 100）。
- 详情页按钮状态用 `GET /api/buyer/favorites/{goodsId}` 返回的 `favorited`，不要靠翻收藏列表判断。

**转收藏**：请求 `{goods_ids:[...]}`，响应 `{moved_count}`；`moved_count` 是真正从购物车转过去的件数，重复转同一批为 0。

### 4.4 商品与类别

- `GoodsSummaryData`：`id`、`name`、`price`、`stock`、`status`、`off_shelf_reason`、`off_shelf_at`、`main_image_url`、`category`、`create_at`、`update_at`。
- `GoodsDetailData` 额外含 `images[]`（`url`、`is_main`、`sort_no`）、`description[]`（`type`、`text`、`url`）、`purchasable`。
- `category` 结构：`{l1_id, l1_name, l2_id, l2_name}`。
- 发布请求：`name`、`price`、`stock`、`category_id`、`description[]`、`main_image`、`gallery_images[]`。

### 4.5 账号、客户与媒体

- 令牌：`{token, expire_at}`；注册/登录请求字段见第 3 节。
- 客户：`{id, username, phone, default_location, create_at}`；列表与详情同结构，详情不含购买历史。
- 媒体上传返回：`{url, kind, size_bytes}`；`kind` 为 `GOODS_IMAGE` 或 `DESCRIPTION_MEDIA`。

## 6. 行为口径

### 6.1 商品

- 两态：`ON_SALE` / `OFF_SHELF`；已下架必须带原因 `MANUAL` / `STOCK_ZERO` / `SOLD_OUT` 与下架时间，在售时两者为 null。
- 手动下架是终态：库存只读，类别仍可改挂；「已售」与「库存耗尽」在库存改回大于 0 时自动上架。
- 有未完成订单（待确认至已发货）时：禁止手动下架、禁止手动把库存改成 0（20020）；改成其他正数不受限。
- 下单只校验在售与库存，不预占；成交扣减到 0 由系统置为 `SOLD_OUT`。

### 6.2 订单

- 六态：`PENDING_CONFIRM` → `CONFIRMED` → `PREPARED` → `SHIPPED` → `COMPLETED`，另有终态 `CANCELED`；整单流转，每次前进一格。
- 买家可在进入「已发货」前取消；卖家可在「交易完成」前取消（含已发货）。取消不影响库存。
- 列表与详情**不含订单项**：先取订单头，再按订单 ID 取明细，两次调用。
- 列表排序固定为下单时间倒序；`status`、`buyer_id`、`goods_id` 三个筛选可任意组合（按商品经订单项反查）。
- 买家只能读自己的订单；他人订单按 60001 处理。卖家可读全部。
- 交易完成按明细数量一次性扣减；任一不足则整单拒绝（60004），订单停在已发货，补货后可重试，不出现部分完成。
- 重复推进返回 60002；**重复取消返回成功**，仅为按钮连点的防抖设计，不是可依赖的业务契约。
- 订单号格式 `SO + yyyyMMdd(UTC) + 6 位序列`，唯一但不是主键。

### 6.3 购物车

- 只存「买家 + 商品 + 加购时间」；数量与勾选不落库、也没有对应接口。
- 「买家 + 商品」唯一：重复加购不新增行，也不刷新加购时间。
- 列表不分页；已下架行保留，`selectable=false`。
- 移除幂等，行不存在也返回成功。
- 转收藏：整批成功或整批拒绝；只转本购物车真实存在的行，`moved_count` 与实际删除行数一致。

### 6.4 收藏

- 收藏、取消收藏都幂等；收藏不要求商品在售。
- 列表按收藏时间倒序分页；已下架行保留，`detail_available=false`。
- 本期不做「收藏转加购」「收藏直接下单」。

### 6.5 权限

- `/api/public/**` 免令牌；`/api/buyer/**` 只接受买家令牌；`/api/seller/**` 只接受卖家令牌。
- 令牌放进程内，后端重启失效；不支持多副本部署。

## 7. 相对阶段二的变化（前端必须知道）

### 7.1 已删除的端点

`/api/buyer/intentions`、`/api/buyer/history`、`/api/seller/goods/{id}/re-list`、`/api/seller/goods/{goodsId}/intentions`、`/api/seller/intentions/{id}/trade|success|failure`、`/api/seller/history/goods`、`/api/seller/history/goods/{id}`。

### 7.2 字段与语义变化

| 项 | 阶段二 | 阶段三 |
| --- | --- | --- |
| 商品状态 | `ON_SALE / FROZEN / OFF_MANUAL / OFF_ZERO` | `ON_SALE / OFF_SHELF` + `off_shelf_reason` |
| 20020 | 商品不在已下架状态 | **有未完成订单**，禁止下架/清零 |
| 20021 | 商品已冻结 | 已下线，不得复用 |
| 客户详情 | 内嵌 `purchase_history` 分页 | 不含购买历史，改查卖家订单列表 `buyer_id` 筛选 |
| 库存扣减 | 裁决成交扣 1 | 交易完成按明细数量一次性扣，全成或全败 |
| 历史 | 归档搬表 + 历史接口 | 无历史表；历史商品 = 已下架商品按原因筛选 |

### 7.3 新增的域

订单（6xxxx）、购物车与收藏（7xxxx）全部为阶段三新增；前端 `types.ts` 与文案映射由前端阶段补齐。

## 8. E2E 注意事项

- 使用独立库 `simple_shop_e2e`，按 E2E 目录说明重建；不要连开发库。
- 启动三个服务时关闭限流（yml 开关），否则批量用例会被 50001 拦住。
- `workers: 1` 串行；默认系统 Edge，不下载 Chromium。
- 订单号带当天日期，不要断言固定值；用前缀 + 正则，或直接从响应里取。
- 时间断言按 UTC 解析后再比对，不要用本地时区硬编码。
- 后端重启会掉会话，用例不要跨重启复用令牌。
- 商品媒体目录是持久卷；用例不要依赖上一轮遗留的图片文件。

## 9. 未做项、已知取舍与遗留

### 9.1 未做项（后端范围外或明确不做）

| 项 | 归属 | 说明 |
| --- | --- | --- |
| 买家端 / 卖家端改造 | 前端阶段（阶段 D / E） | 含 `api/types.ts`、错误码文案、页面交互 |
| E2E 用例重写 | E2E 阶段 | 意向/裁决用例作废，按新契约重写 |
| 多副本、无状态会话 | 不做 | 会话在进程内，backend 不能水平扩展 |
| 库存预占 | 不做 | 已确认接受「先完成者得」的超卖风险 |
| 订单搜索、导出、状态时间线、备注、物流 | 不做 | 不在阶段三需求范围 |
| 在线支付、退款、售后 | 不做 | 系统只承载订单流程，不承载支付与物流 |

### 9.2 已知取舍

| 项 | 说明 | 影响 |
| --- | --- | --- |
| 无预占可能超卖 | 两笔订单可同时下单，先完成者得，后者完成时整单缺货拒绝 | 已确认接受；前端需展示 60004 的可读提示 |
| 单副本会话 | 会话在进程内，重启失效，不能多副本 | 部署与 E2E 都不要按无状态服务设计 |
| 重复取消幂等 | 返回成功只是防抖 | 不要把它当业务规则写用例或文案 |
| 客户购买历史 | 不内嵌客户详情，改查订单列表 | 前端客户详情页需要跳转入口 |
| 订单明细两次调用 | 列表/详情不带明细 | 详情页需要处理「头成功、明细失败」的部分失败 |
| OpenAPI 无变更日志 | 本次只有 1.0.0 快照 | 后续接口变更需重新生成并更新本文件 |
