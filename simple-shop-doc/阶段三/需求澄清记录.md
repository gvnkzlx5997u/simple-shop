# 需求澄清记录
针对挑战需求B，对用户进行提问，得到了以下需求澄清记录

## 问题1

### 问：
1. B 的「下单」和已实现的「意向排队」什么关系？同一商品能同时排队和下单吗？B 上线后排队机制还保留吗？
2. 「交易完成前商家可取消」——已开始发货的订单商家也能取消吗？发货后取消怎么处理（召回？退款？）？
3. 购物车多件下单，是生成 1 个含多商品明细的订单，还是每件商品各 1 个订单？5 个状态是整单流转还是逐商品流转？
4. 下单时就扣库存，还是商家确认后才扣？取消订单时库存什么时候返还？
5. 5 个状态分别谁推进：商家确认/备货/发货是商家手动点吗？「交易完成」是客户确认收货、双方确认，还是超时自动完成？状态能跳过或回退吗？

### 答：
（需求澄清·挑战B）逐条说：
1. 这个顺着机制推：以前是「提交购买意向 → 先到先得排队 → 线下交易」，现在改成了「购物车 → 下单 → 订单状态流转」。那有了购物车和订单之后，同一商品还需要「先到先得排队」吗？自然也就不存在「又排队又下单」的并存——你团队顺着这个方向定。
2. 能取消。「开始发货」仍处在「交易完成」之前，所以商家照样可以取消。发货后取消不涉及退款、也不存在召回——因为本系统没有在线支付，线下「一手交钱、一手交货」，钱货没交付前都能取消；一旦标记「交易完成」，就不可再取消。
3. 生成 1 笔订单，含多商品明细（不是每件各 1 单）。5 个状态是整单（订单级）流转，不逐商品流转。
4. 下单不扣库存（下单只校验库存，不足的提示缺货）；商家确认时也不扣。库存扣减发生在**「交易完成（成交）」时**。取消订单后，订单里各商品库存立即回补（每件 +1，重新可售）。
5. 5 个状态全部由商家在后台手动推进：商家确认、备货完成、开始发货、交易完成都是商家点。「交易完成」是卖家标记（线下交易完成后），不是客户确认收货、不是双方确认、也没有超时自动完成。状态只能按序推进，不能跳过、不能回退；客户侧只能查看，不能推进。

## 问题2

### 问：
1. 挑战需求B中商品的状态是否只剩下“在售”与“已下架”两种了？
2. “已下架”是商品的终态吗？
3. 如果不是，商品什么时候进入终态（即进入历史商品，不能再次上架变为在售）？

### 答：
1. 对，只剩「在售」和「已下架」两种了。挑战 A 那个「已冻结（交易中）」状态没了——它是购买意向、先到先得排队那套机制里的，挑战 B 用订单取代了购买意向，商品就不用再冻结了。
2. 「已下架」不都是终态：库存耗尽（库存归 0）下架的，补货后能重新上架。
3. 挑战 B 里商品其实没有「永久终态」这一说——挑战 A 那种「交易成功下架就永久进历史、再也不能上架」的设定，跟着购买意向机制一起废弃了。现在「历史商品」就是「已下架」的统称，库存耗尽的补货之后还能重新挂出来卖。

## 问题3

### 问：
我举个例子：库存 1，买家 A、B 各下一单（不预占）。A 先成交，库存扣到 0；B 取消，如果按“取消回补”再 +1，库存变回 1，但货已经卖给 A 了——同一件货被算了两次。那么“取消后库存 +1”，是指“释放预占”；还是说库存应当没有预占机制，取消订单不影响库存，交易完成才动库存。

### 答：
你抓得对，这个例子正好点出一个矛盾。这个版本库存没有预占机制——下单只校验库存、不锁定（购物车更不锁），真正扣库存是交易完成那一刻。
所以「取消回补 +1」在无预占模型下不成立：取消发生在成交之前，订单根本没扣过库存，没有货可回补。按你说的第二种理解才对——取消订单不影响库存，交易完成才动库存。A 成交、B 取消这个例子里，库存应该停在 0，不该回补成 1。

## 问题4

### 问：

1. 取消订单后，这个订单语义上不属于5个状态中的任意一个。订单是否应当新增独立的“已取消”状态，还是共用交易完成状态？
2. 是否区分“买家取消 / 卖家取消”并落实到前端文案上？
3. 取消后订单是否仍出现在卖家订单列表，卖家订单管理是否需要订单历史存放终态订单？
4. 取消的订单是否计入买家的购买历史，或是出现在买家的订单列表中？
5. 是否记录订单取消时间及取消原因，如需记录取消原因，买卖双方是否都可查看这个字段？

### 答：

1. 新增独立的「已取消」状态。订单标记为已取消，它不是共用交易完成。
2. 取消的权限和时机区分了买卖双方（客户在「开始发货」前可取消，商家在「交易完成」前可取消），但取消后统一标「已取消」，没要求前端文案区分是谁取消的。
3. 没有单独定义「卖家订单列表」和「订单历史」模块。卖家看订单的入口是「每个客户的购买历史」、「每个商品的订单记录」，以及后台推进状态。取消的订单是否仍显示、要不要单独的历史归档，都没规定。
4. 取消的订单计入买家的下单历史，它的「订单状态/最终结果」就是已取消。
5. 不记录取消时间和取消原因。列的订单字段只有订单号、商品清单、总金额、下单时间、状态/最终结果，没有取消时间、取消原因这两项。

## 问题5

### 问：
1. 如果不预占商品库存，备货完成、开始发货两个状态下库存为0怎么办？这两个阶段的语义可能不是很严谨，接受此风险还是添加校验，在卖家更改订单状态到备货完成时，统计所有备货完成与开始发货订单，判断库存数量能否满足，不满足就不能更改订单状态为备货完成。 
2. 上一阶段的手动改库存为0/手动下架，在这一阶段，怎么处理已有订单，还是说使用最保守的做法：有非终态订单不允许这两个操作？

### 答：
1. 不添加那个校验，接受这个风险。库存逻辑就是两步：下单时校验够不够（不够不让下单），交易完成时才真正扣库存。备货完成、开始发货这两个中间状态不额外校验库存。
2. 这个版本没明确规定「手动改库存为 0 / 手动下架时，已有的非终态订单怎么办」。按最保守的做法来是合理的——有非终态订单（还在下单、确认、备货、发货状态）就不允许手动改库存为 0 或手动下架，先把订单处理完再说。

## 问题6

### 问：
1. 加入购物车时可以选择购买数量吗（例如同款买 3 件）？
2. 若支持，上限受库存约束还是不限？商家手动把库存改为 0 时，商品是否自动下架？还是允许「在售、无货」状态

### 答：
1. 加购数量：支持同款多件——购物车列表就有「数量」字段，客户可以调整数量。上限：购物车阶段不锁定库存、不设限，真正下单时才校验库存，库存不足的会提示缺货、不能下单。
2. 手动库存改 0：会自动下架。规则是「库存减至 0 时商品自动下架」，不管是成交扣到 0、还是你手动改成 0，结果一样——不存在「在售、无货」这种状态。补货（库存改回正数）后再由卖家手动重新上架。

## 问题7

### 问：
是否沿用「商品发布后不可改」？本版本要不要做退货 / 退款 / 售后？客户下单后能改订单吗？（改数量 / 部分商品取消 / 改联系地址）

### 答：
1. 「商品发布后不可改」：没有这条硬规则。能确认的是库存发布后可以手动调整（补货）。至于名称/价格/描述/类别发布后能不能改，你们当待确认点或自行补全都行。
2. 退货/退款/售后：不做。本系统无在线支付，线下「一手交钱、一手交货」；交易完成后订单就结束，没有退货、退款、售后流程（取消订单也不涉及退款）。
3. 下单后改订单：不能改。下单后客户只能「查看状态」和「整单取消」（发货前可取消），没有改数量、部分商品取消、改地址这些操作。而且订单字段里根本没有「地址」——「默认交易地点」是账号级的选填项，不落在订单上。

## 问题8

### 问：
1. 订单详情页要不要
2. 商品能否删除、订单是否存商品快照
3. 收藏 ↔ 购物车双向互通（收藏能直接加购/下单吗）
4. 需求A/B 是二选一还是都做、存量数据要不要迁移

### 答：
1. 订单详情页：需求里没把「订单详情页」作为独立功能点定义。订单有信息字段（商品清单、总金额、下单时间、状态），客户和商家要能查看，但「独立详情页还是列表展开」这种交互细节，需求没写死。
商品删除：不能删。商品退出只有「下架」一种方式（手动下架 / 库存 0 自动下架 / 交易成功下架），下架后进「历史商品」列表，没有物理删除。
2. 订单快照：订单里记录的是商品清单（名称、单价、数量）——就是下单当时的定格信息，相当于快照。但「下单后改价/改描述，历史订单变不变」这种细节，需求没单独写，按「下单即定格」理解即可。
3. 收藏 ↔ 购物车：购物车 → 收藏有（购物车多件可转收藏）；收藏 → 直接加购/下单没定义——收藏列表只点进商品详情，从收藏直接加购物车或下单的入口，需求里没有。
4. 需求A/B 二选一还是都做：都做。B 是 A 的升级迭代，在 A 已实现的基础上叠加（收藏、购物车、订单），不是二选一；只有被订单替代的那部分（购买意向/排队）才下线。
存量数据迁移：不在需求范围内，需求没定义数据迁移的事。

## 问题9

### 问：
1. 手动下架、库存为0自动下架、手动调库存为0时，这些情况共用同一个“已下架”状态，还是要区分来源并在卖家前端展示？
2. 已下架商品的库存可能>0也可能=0，重新上架时的操作有没有区别？
3. 买家的收藏、购物车中若有已下架商品，怎么处理？ 
4. 已下架商品对买家的可见性？

### 答：
1. 状态上共用一个「已下架」，但来源在卖家后台的历史商品里是区分开的——分了「已售」「库存耗尽下架」「手动下架」三类，前端可以按这个区分展示。
2. 有区别。库存归 0 下架的，补货（把库存调回大于 0）就重新上架；手动下架的（库存本来就大于 0），没有「补货」这一步，也没有单独定义的上架动作。
3. 收藏里的已下架商品保留，但标注「已下架/无货」；购物车里的已下架商品没明确说怎么处理，只是下单时会校验库存、缺货的商品下不了单。
4. 已下架商品对买家默认不可见——买家浏览、搜索的都是「在售」商品，下架后不再展示。例外是收藏里会保留并标注「已下架/无货」。

## 问题10

### 问：
1. 购物车/收藏/订单有没有数值上限？
2. 对于重复提交订单，下单频率是否限制，或是同一买家的未完成订单有无上限？
3. 订单有没有定时任务，例如超时自动取消？
4. 买家能对购物车中的商品做哪些操作，例如加购/删除/改数量/清空/全选？ 
5. 买家提交订单的入口在哪里，除了购物车外，在商品详情中是否允许买家直接对某一商品提交订单？

### 答：
1. 没有数值上限。购物车、收藏、订单都没设数量限制。
2. 不限制。明确允许同一买家同时有多笔不同状态的订单，没有下单频率限制，也没有未完成订单数量上限。
3. 没有定时任务，没有超时自动取消。取消只能由客户（发货前）或商家（完成前）手动触发。
4. 明确支持的只有：加购、改数量、移除商品。清空、全选这些没要求。
5. 提交订单的入口是购物车——从购物车选多件商品一起下单。商品详情页不能直接下单，得先加入购物车，再从购物车下单。

## 问题11

### 问：
手动下架的商品能否重新上架？如果不能，这个商品的状态是否就等同于被删除了？

### 答：
手动下架的商品，这个版本没定义重新上架的操作——「补货后重新上架」只针对库存归 0 下架的情况，手动下架（库存还大于 0）没有对应的上架入口，所以它实际上就是终态。但它不等于删除：手动下架后商品进历史商品，卖家后台还能看到记录；这个版本里也根本没有「删除商品」这个概念，最接近的就是手动下架（永久退出在售，但记录保留）

## 问题12

### 问：
1. 交易完成扣到0能否恢复在售？
2. 前端UI上，补货后是自动上架还是必须点“重新上架”？
3. 注册时默认交易地点是选填，那么订单记不记地址？

### 答：
1. 能复售。交易完成扣到 0，跟「卖家把库存改 0」行为一样——都是库存归零自动下架，补货后重新上架。挑战 A 那种「卖完就永久终态」已经废弃了；「已售」只是历史分类标签（表示它是卖出去的），不影响复售。
2. 补货后自动上架。库存从 0 改回大于 0，商品自然回到在售，不用额外点「重新上架」按钮。
3. 订单不记地址。订单字段只有下单客户、商品清单、总金额、下单时间、状态；默认交易地点是注册时填的（选填，用于线下交易撮合），订单本身不记这个地址。

## 问题13

### 问：
1. 存在订单部分缺货的情况：多个订单抢最后一件，或一笔订单里某个商品被别的订单买走，卖家点“交易完成”时库存不足，整单失败、部分完成、自动取消，还是允许负库存？
2. 卖家是否需要全局的“订单管理/待处理订单”页面？还是只能从客户购买历史、商品订单记录里找？取消的订单在这些页面是否显示？
3. 已下架商品在购物车、收藏里，能否打开详情？购物车里保留置灰、自动删除，还是结算时跳过？
4. 手动下架进“历史商品”，“历史商品”是否保留独立页面？还是与已售/库存耗尽下架同时展示？
5. 买家是否能看到进行中的全部订单并取消？卖家客户购买历史、商品订单记录是否包含进行中/已取消订单？取消是点一下立即生效，还是需要对方确认/审批？
6. 有非终态订单时，能否把库存改到低于未完成订单数量的正数？

### 答：
1. 不允许负库存——原则上要「避免超卖」。但「交易完成时库存不足」具体怎么处理（整单失败、部分完成、自动取消），这个版本没规定，只定了下单时校验、成交时扣减、避免超卖这三条。
2. 没明确定义全局「订单管理/待处理订单」页面。卖家操作订单（推进状态、取消）的入口就是「客户购买历史」和「商品订单记录」这两处；是否要一个全局列表、取消订单是否显示，都没规定。
3. 收藏里的已下架商品保留并标注「已下架/无货」（能否点开详情没明确）；购物车里的已下架商品没明确处理，只是下单/结算时会校验库存、缺货的会被拦下。置灰、自动删除、结算跳过这些具体做法都没写。
4. 历史商品是统一展示的——已售、库存耗尽下架、手动下架都在「历史商品」里，手动下架没有独立页面。
5. 买家能看到进行中的订单并取消（发货前可取消）；卖家看客户购买历史/商品订单记录是否包含进行中、已取消订单，没写清楚；取消是点一下立即生效，没有对方确认/审批环节。
6. 没规定。手动调库存没有「不得低于未完成订单数量」的限制，但这样改会让后面订单成交时库存不足，落到第 1 条那个没定义的场景里。

## 问题14

> **性质说明**：本问**不向客户提出**，是团队内部确认（2026-11-07）。依据是 Q7 答 1——客户明确说「名称/价格/描述/图片/类别发布后能不能改，你们当待确认点或自行补全都行」，即已授权团队自决。因此下文的答复是**团队决策，不是客户答复**，引用时不要写成「客户确认」。

### 问：

商品发布后，名称、价格、描述、图片、类别、库存分别允不允许修改？

### 答（团队决策）：

沿用阶段二口径：

1. **名称、价格、描述、图片**：发布后不可修改，本期**不新增商品编辑页**。
2. **库存**：可随时调整（补货、改为 0）。
3. **二级类别**：可改挂；入口沿用阶段二的做法，**只在「删除类别」流程里出现**（类别下有商品时不能直接删，须先改挂）。
4. **手动下架的商品是终态**：库存与类别一并只读，不可再改（见《需求澄清初步分析》§0.1 的 D6）。

> 阶段二「交易中禁止改挂类别」的限制随冻结机制一并作废——阶段三没有「交易中」这一商品状态。
