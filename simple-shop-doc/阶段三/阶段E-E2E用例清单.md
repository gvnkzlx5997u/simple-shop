## 2. 为什么大部分要动

三类原因，叠加起来导致「大部分用例要么改选择器、要么改断言、要么整条消失」：

| 原因 | 具体变化 | 对用例的影响 |
| --- | --- | --- |
| 交易模型整体替换 | 意向 / 排队 / 裁决 / 冻结 / 归档 / 重新上架 / 四态商品 / 购买历史 / 历史两页 全部下线，换成订单六态 | `04` 整组、`06` 三条、`03` 两条、`07` 两条直接失效 |
| 卖家端 UI 改版（阶段U） | 原生 CSS → Tailwind + daisyUI；状态标签、卡片、筛选、错误提示的 DOM 全变 | 几乎所有卖家端断言的选择器要重写（语义断言可留） |
| 买家端重写（阶段D） | 「我要购买」→ 加购 / 收藏 / 购物车 / 订单；`/history` 删除；金额统一两位小数 | `02` 两条失效；价格断言 `¥99.9` → `¥99.90` |

## 7. 买家端遗留脚本（`d3-cart-check.js` / `d5-full-regression.js`）怎么处理

| 项 | 处置 | 理由 |
| --- | --- | --- |
| 是否并入 `tests/` | **不并入** | 两者用 `playwright`（非 `@playwright/test`）启动、依赖固定夹具（`GD-D1-*`）与数据库写权限，本质是「阶段性证据脚本」；`playwright.config.ts` 的 `testMatch` 只收 `tests/**/*.spec.ts`，放在根目录不会被误跑 |
| 数据库访问 | **已改为 node 直连**（`scripts/db.js`，mysql2） | 原来拼 `mysql -e ...` 过 `cmd.exe`：依赖 CLI 安装路径、多行 SQL 只执行第一段、中文要额外指定字符集。现在参数化、跨平台、失败信息带库名与 SQL |
| 保留价值 | 保留（原样） | 「页面算的钱 = 库里存的钱」这类对账，UI 层断言做不到；继续作为阶段性证据脚本 |
| 其中可迁的 | 见 §5.4 | 8 条纯 UI 断言迁进 Playwright，让「买家端行为」也进主套件 |
| 注意 | `d5` 依赖固定 ID 的夹具与 `simple-shop-d1-fixtures.sql` | 与 E2E 主库 `simple_shop_e2e` 是两套数据，跑之前别混库 |
