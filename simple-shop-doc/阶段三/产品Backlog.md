# 产品 Backlog（阶段三 · 挑战需求 B）

> **用途**：第三次阶段性评审材料；内容逐条录入禅道「在线购物系统-第14组 → 需求」。
> **范围**：挑战需求 B 的 B.1（订单升级）+ B.2（商品预选升级），以及由此触发的商品状态两态化改造。
> **不含**：数据库重建、限流改造、旧接口下线、后端分包重构——这些属**开发任务**，不进产品 backlog（见《需求澄清初步分析》§5.3）。
> **依据**：《挑战需求B》原文 7 条、《需求澄清记录》Q1–Q14、组长《需求澄清初步分析》v0.4、阶段二《状态模型设计》。

### 估算是怎么来的

按功能点拆，每个点分别估前后端再相加。口径是**熟练开发者的纯开发时间**，不含调试与返工；对不熟悉技术栈的人，实际通常是估算的 **1.5～2 倍**。这是**初始估算**，做完前两条后按实际耗时校准。

### 本版被推翻的阶段二口径（写故事时容易照抄错）

| 阶段二 | 阶段三 |
| --- | --- |
| 购买意向 + 先到先得排队 | **订单**取代意向，排队机制整体下线 |
| 商品四态：在售 / 冻结 / 手动下架 / 库存清零下架 | **两态**：在售 / 已下架（下架原因另记） |
| 手动下架可点「重新上架」 | 手动下架是**终态**，无重新上架入口 |
| 补齐库存后要手动点重新上架 | 库存从 0 改回 >0，**自动上架** |
| 成交且卖完最后一件 → 搬进历史表「归档」 | **不搬表**，单表 + 下架原因 + 历史视图 |

## 六、每条故事的验收标准（录入禅道「验收标准」字段用）

### 订单域

**1 购物车多选下单**
- 只能对「在售」商品下单，已下架商品不能提交
- 从购物车勾选 N（N≥1）件商品提交，生成 **1 笔**订单、N 条明细，不是 N 笔订单
- 总金额由服务端按 Σ(单价 × 数量) 计算，前端传值不采信
- 下单**不锁库存**：下单后商品仍在售、库存不变
- 任一明细数量 > 当前库存 → **整单拒绝**，提示具体商品；不允许「部分成功」
- 下单成功后只移除被选中的购物车行，未选中的保留

**2 我的订单列表（买家）**
- 只显示自己的订单；进行中、交易完成、已取消**都要显示**（即全部订单）
- 字段：订单号、商品清单（或件数）、总金额、下单时间、状态
- 按提交时间倒序，支持翻页
- 不做超时自动取消，不存在「过期」状态

**3 买家取消订单（发货前）**
- 状态为「待确认 / 已确认 / 备货完成」时可取消；「已发货」「交易完成」「已取消」不可取消
- 取消前有二次确认
- 点一下立即生效，**无对方确认/审批**
- 取消后订单状态为「已取消」，**库存不变**
- 取消后商品不自动回购物车、不自动回收藏

**4 订单详情页（买卖双方共用）**
- 买卖双方看到同一页面、同一套字段；按角色显示不同操作按钮
- 字段：订单号、商品清单（名称/单价/数量）、总金额、下单时间、状态、下单客户
- 商品即使已下架，明细仍能正常显示（读快照 + 引用）
- 订单不展示地址字段

**5 卖家订单管理页**
- 六个状态各一个 tab（含「已取消」），可切换
- 列表字段与订单列表一致；点行进入订单详情
- 只显示与自己商品相关的订单

**6 卖家推进订单状态**
- 状态只能按「待确认 → 已确认 → 备货完成 → 已发货 → 交易完成」单向推进
- 不可跳过、不可回退；非当前可推进状态时按钮置灰且接口拒绝
- 只有卖家能推进；买家侧无推进按钮
- 无超时自动流转
- 推进「备货完成」「开始发货」时**不做**库存校验（`Q5` 答 1：中间状态不代表库存充足；库存只在交易完成时校验，见第 8 条）

**7 卖家取消订单（完成前）**
- 「待确认 / 已确认 / 备货完成 / 已发货」都可取消；「交易完成」「已取消」不可
- 取消后状态为「已取消」，库存不变
- 无退款、无召回流程

**8 交易完成扣库存与缺货拦截**
- 交易完成时按明细数量扣减库存，扣减与状态变更同一事务
- 任一行库存不足 → **整单不允许完成**，返回具体缺货明细；不扣成负数、不部分完成、不自动取消
- 扣减后库存为 0 → 商品自动下架（原因记为「已售」）
- 卖家可重试：补货后再次点「交易完成」应成功

**9 卖家按客户/按商品查订单**
- 客户维度：某客户的全部订单，含进行中、交易完成与已取消
- 商品维度：某商品的全部订单
- 两个入口都进入同一个订单详情页，不重复实现两套详情

### 购物车域

**10 加入购物车**
- 同一买家对同一商品重复加购，不产生重复行
- 加购不校验库存上限、不锁库存；商品下架后仍可存在行（但不可选中）
- 未登录不能加购

**11 购物车列表与改数量/移除**
- 每行可改数量、可移除；小计与总价随数量实时变化
- 支持一次勾选多件
- **不提供**「清空购物车」「全选」按钮（`Q10` 答 4 客户没要求；`F2` 已确认不做）
- 数量是前端临时状态，**服务端不持久化**（刷新/换设备会回到默认值）

**12 购物车多件转收藏**
- 勾选多件 → 移入收藏：购物车行删除，收藏新增对应记录
- 已收藏的不重复新增
- 反向（收藏 → 加购/下单）本期不做

**13 购物车失效商品处理**
- 已下架商品仍在购物车中显示，标注「已下架」
- 该行勾选框禁用，不能被选中结算
- 在售但库存不足的商品仍可选中，结算时整单拒绝并提示

### 收藏域

**14 收藏 / 取消收藏**
- 登录后可收藏、可取消收藏；同一商品不重复收藏
- 收藏记录只存买家、商品、时间，不做商品快照
- 未登录不能收藏

**15 我的收藏列表**
- 只显示自己的收藏，按收藏时间倒序
- 已下架商品保留展示，标注「已下架/无货」
- 已下架商品不可进入详情页

### 商品改造域

**16 商品两态化（废除冻结）**
- 商品状态只有「在售」「已下架」两个取值
- 不存在「冻结 / 交易中」状态
- 有进行中的订单不影响商品在售状态，商品仍可被下单

**17 手动下架改为终态**
- 手动下架前二次确认，文案明确提示不可重新上架
- 手动下架后：无重新上架入口、不可改库存、不可改类别
- 商品仍可在「历史商品」中查看，记录不删除
- 接口层也要拒绝写操作，不能只靠前端禁用

**18 库存归零下架与补货自动上架**
- 库存改为 0（无未完成订单时手动改，或成交扣减至 0）→ 自动下架
- 库存从 0 改为 >0 → **自动**回到在售，无需点按钮
- 自动上架仅适用于「库存耗尽」「已售」，手动下架的商品不适用
- 自动上架后清空下架原因与下架时间

**19 历史商品页（区分三类来源）**
- 一页展示全部已下架商品，按「已售 / 库存耗尽下架 / 手动下架」标注并可按来源筛选
- 手动下架无独立页面
- 补货复售的商品从历史页消失，回到在售

**20 非终态订单时禁止下架/清库存**
- 商品存在非终态订单（待确认/已确认/备货完成/已发货）时，手动下架与改库存为 0 均被拒绝并给出明确提示
- 改成其他正数不拦
- 订单全部进入终态（完成/取消）后，两个操作恢复可用

## 八、禅道粘贴稿（按阶段二 #13892 的样式）

> 样式约定：**需求描述** = 一句话用户故事；**验收标准** = 数字编号、每条一句完整的话，写到按钮与页面可见的行为为止。内容与 §六 一致，仅排版不同；粘贴时整段复制。

**1｜购物车多选下单**

需求描述：

```
作为一名买家，我希望在购物车勾选多件商品一次性下单，以便一次买齐多件商品。
```

验收标准：

```
1. 只能对「在售」商品下单，已下架商品不能提交。
2. 从购物车勾选 N（N 不小于 1）件商品提交，生成 1 笔订单、N 条明细，不是每件商品 1 笔订单。
3. 总金额由服务端按「单价 × 数量」求和计算，不采用前端传的金额。
4. 下单不锁库存：下单后商品仍在售，库存数不变。
5. 任一明细数量大于当前库存时整单拒绝，提示具体商品，不允许部分成功。
6. 下单成功后只移除被选中的购物车行，未选中的保留。
```

**2｜我的订单列表**

需求描述：

```
作为一名买家，我希望查看自己的全部订单，以便随时掌握每笔交易的进展。
```

验收标准：

```
1. 买家登录后进入「我的订单」，列出自己的全部订单，包含进行中、交易完成与已取消。
2. 每行显示订单号、商品名（多件时显示件数）、总金额、下单时间、当前状态。
3. 列表按下单时间倒序排列，支持翻页。
4. 没有超时自动取消，订单不会因超时改变状态。
```

**3｜买家取消订单（发货前）**

需求描述：

```
作为一名买家，我希望在卖家发货前取消整笔订单，以便及时反悔。
```

验收标准：

```
1. 订单状态为「待确认 / 已确认 / 备货完成」时买家可取消；「已发货」「交易完成」「已取消」不可取消。
2. 取消前有二次确认。
3. 取消立即生效，不需要对方同意。
4. 取消后订单状态变为「已取消」，库存数不变，商品不自动回购物车或收藏。
```
