## 1. 前置与口径

### 1.1 环境（缺一项就会成片失败）

| 项 | 要求 | 原因 |
| --- | --- | --- |
| 数据库 | `simple_shop_e2e`，跑前 `npm run db:reset`，由 Flyway 跑到 **V4** | V4 给订单加的是 `NOT NULL` 无默认值的收货快照列，**订单表必须为空**才能建，不能关校验硬绕 |
| `DB_URL` | 指向 `simple_shop_e2e` | 不能连开发库 `simple_shop` |
| `RATE_LIMIT_ENABLED` | `false` | 批量注册 / 登录会被 50001 拦，E2E 不做限流断言 |
| `MEDIA_DIR` | `./target/test-media`，**每轮跑前清空** | 售后凭证图落在磁盘上，不清会跨轮累积 |
| `PAYMENT_MOCK_ENABLED` | `true`（默认） | 四渠道恒成功；关闭且无真实渠道时一律拒绝 |
| `PAYMENT_MOCK_FAIL_CHANNELS` | 主批次留空；仅 `CO-09` 批次设 `ALIPAY` | 支付失败只能靠配置注入，不能靠改请求参数 |
| `ORDER_PAYMENT_TIMEOUT` / `ORDER_TIMEOUT_SCAN_INTERVAL_MS` | 主批次用默认 `24h` / `60000`；仅 `CO-13` 批次设 `1m` / `5000` | 24 小时超时不进主流程 |
| 三个服务 | 后端 `:8080`、买家 `:5174`、卖家 `:5173` | 买家 dev server 只监听 `[::1]`，写 `localhost` 不要写 `127.0.0.1` |
| 浏览器 | 系统 Edge（`channel: 'msedge'`）、`workers: 1` | 不变 |

### 1.2 数据

- **造数一律走接口，断言一律走页面 / 接口返回**，测试脚本不连数据库（`scripts/db.js` 只用于重建库与手工夹具）。
- 账号与商品名带 `RUN_ID` 后缀；用例之间不依赖上一轮残留。
- 每个需要下单的买家必须先有地址：新买家首条地址自动默认，`placeOrder` 由此不再需要显式传地址（见 §1.4）。
- 单号只断言格式：订单 `SO + yyyyMMdd + 6 位`、售后 `AS + yyyyMMdd + 4 位`，同日多轮序号会累加。
- 金额形如 `¥245.50`；金额由后端算，前端传的金额被忽略，不写「前端算出一个数再比」的断言。

### 1.3 固定行为（可直接断言）

- 未登录访问任何 `requiresAuth` 路由 → `/login?redirect=<原路径>`；401 同样统一跳登录。
- 「去结算」跳 `/checkout`；提交订单在 `checkout-submit`；下单成功跳 `/orders/:id`。
- 支付成功跳回 `/orders/:id?paid=1`，详情页显示「支付成功」。
- 买家侧取消订单、确认收货、删除地址都是**内联二次确认**（`确认 X` / `再想想`）；卖家侧确认类动作用 `role="dialog"` 弹窗 + 按钮文案。
- 卖家发货 / 改物流共用 `logistics-dialog` 弹窗，提交按钮 `logistics-submit`；买家地址表单在 `address-form` 内，Esc 不关闭、点遮罩或取消才关。
- 售后入口只在**交易完成**订单的明细行出现，带 `order_item_id`（不要用 `goods_id` 定位）。
- 倒计时来自 `pay_deadline`，不按 24 小时自己算；归零只提示 + 给「刷新」，不本地改状态。

### 1.4 helpers 统一改造（保留用例「零改动」的前提）

这一节不是用例，但决定了 63 条保留用例能否原样跑。改造集中在三个文件 + 一个新文件：

| 文件 | 改动 |
| --- | --- |
| `helpers/api.ts` | ① `OrderStatus` 改七态（`PENDING_PAYMENT`/`PAID` 补上，删 `PENDING_CONFIRM`）；② `placeOrder` 增加可选 `addressId`，缺省时自动为该买家建一条默认地址并缓存（**保留用例因此不用改调用点**）；③ 新增地址 5 个、支付、确认收货、买家售后 4 个、卖家售后 4 个、改物流 1 个封装；④ `advanceOrder` 的 `'complete'` 删除，`ship` 必须带 `{carrier, tracking_no}`；⑤ `OrderRow` 补 `receiver_*`、`payment_channel`、`paid_at`、`pay_deadline`、`carrier`、`tracking_no`、`refunded_amount`、`aftersale_count`；`OrderItemRow` 补 `order_item_id` |
| `helpers/data.ts` | `buyerFixture` 去掉 `default_location`；新增 `addressFixture`、`aftersaleFixture` |
| `helpers/ui.ts` | `buyerRegisterUi` 去掉 `location` 参数（并断言页面上没有该字段）；新增 `buyerOpenCheckout`、`buyerPayOnPage`、`buyerConfirmReceiptOnPage`、`sellerShip`（填物流弹窗）、`sellerOpenAftersale`、`openAftersaleApplyViaUI` |
| `helpers/files.ts`（新） | 生成 1×1 PNG 与超限图片（复用 `05-contract` 里已有的 buffer 写法），供 `AS-04` / `AS-05` 上传 |

> 改造完成后，保留用例的 spec 文件**不需要编辑**：地址、状态、七态筛选的差异全部收敛在 helper 里。若实现时发现某条保留用例仍需改动，说明 §1.4 的改造没做到位（或该条被判错了），应当补 helper 或把它挪进 §3，而不是就地改断言了事。

## 3. 修改（26 条）

每条只写**失效点**与**改后的步骤 / 预期**，其余断言沿用原用例。

### 3.1 注册（1 条）

| 编号 | 场景 | 失效点 | 改法 |
| --- | --- | --- | --- |
| T01-04 | 买家注册 → 自动登录并进商品列表 | 注册表单已无「默认交易地点」，`buyerRegisterUi` 仍填该字段会 400 | 去掉地址输入；补断言 `getByLabel('默认交易地点')` 数量为 0；注册后跳 `/goods`；再进 `/addresses` 应为空态（新买家没有地址）。接口层另断言：注册多传 `default_location` → 400 + 50002 |

### 3.2 结算入口（3 条）

| 编号 | 场景 | 失效点 | 改法 |
| --- | --- | --- | --- |
| T02b-07 | 勾选两件去结算：生成 1 笔订单、明细 2 行、回购物车空态 | 点 `cart-checkout` 后不再直接下单，先到 `/checkout` | `cart-checkout` → 断言 URL `/checkout`、`checkout-total` 等于勾选行合计、默认地址已预选、清单 2 行 → `checkout-submit` → `/orders/:id`（待支付）→ 明细 2 行 → 回 `/cart` 空态 |
| T02b-15 | 下单瞬间商品下架：被拦并自动刷新显形失效行 | 提交动作从购物车移到结算页 | 停在 `/checkout` 时用接口下架该商品 → `checkout-submit` → 提示「有商品已下架，请回购物车处理」；`listBuyerOrders` 总数不变；回 `/cart` 该行置灰、不可勾选 |
| T02b-16 | 下单瞬间库存被改小：20015 拦截且不产生订单 | 同上 | 停在 `/checkout` 时把库存改到小于数量 → 提交 → 提示「库存不足，请回购物车调整数量」；订单总数不变 |

### 3.3 七态口径（11 条）

| 编号 | 场景 | 失效点 | 改法 |
| --- | --- | --- | --- |

### 5.2 明确不做进 E2E

- 真实支付渠道：本期只有 Mock，签名 / 回调 / 渠道错误码无从验证；支付宝沙箱是可选扩展，不在本轮。
- 物流轨迹节点、结构化省市区地址：契约 §8 已列为未做。
- 退款失败与重试：后端无失败态、无补偿任务。
- 图片上传的真实弱网与浏览器端类型拦截：前端有校验与单测，浏览器端只覆盖正常上传与张数上限。
- 多标签页并发购物车、移动端适配、视觉细节（配色 / 间距）、性能指标：靠人工与 `npm run perf`，不进断言。
- 日志类断言：始终不断言审计日志与运行日志（`AGENTS.md` §4）。

## 6. 执行与验收

### 6.1 批次划分

| 批次 | 内容 | 命令 |
| --- | --- | --- |
| A 主批次 | 13 个 spec（不含 `CO-09`、`CO-13`） | `npm run clean && npm run db:reset && npx playwright test --grep-invert "CO-09|CO-13"` |

每批之前：重建 E2E 库（V4）、清空 `target/test-media`、确认三服务在线、关闭限流。

### 6.2 通过标准

- A 批全绿；B / C 批各自全绿并单独记录（它们依赖非默认配置）。
- 提交前必须跑 `npm run typecheck`：Playwright 只转译不查类型，类型错误只能在这一步拦。
- 失败必须留 `evidence/` 与 trace；确认原因后清理，不带着旧证据跑下一轮。
- 预计耗时：原 90 条约 1.5 分钟，新增 53 条含上传与多轮支付，估 **3–4 分钟**（`workers: 1`）。
