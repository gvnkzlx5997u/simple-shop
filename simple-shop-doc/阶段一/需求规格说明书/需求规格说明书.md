## 术语与缩写

### 业务术语

| 术语 | 定义 |
| --- | --- |
| 卖家 | 系统唯一账号持有者，商品的发布者与所有状态的裁决者 |
| 买家 | 无需注册的访客；提交购买意向后成为「意向购买人」 |
| 商品 | 卖家发布的一件待售物品，含名称、描述、图片、价格 |
| 购买意向 | 买家对某件商品提交的一次购买申请，是排队与交易的载体 |
| 意向队列 | 某件商品下所有处于「排队中」状态的意向，按排序序号升序排列 |
| 队首 | 意向队列中排序序号最小的那条意向 |
| 口令码 | 系统在买家提交意向成功后当场生成并展示的**唯一凭证**，买家凭它查询与操作自己的意向 |
| 进入交易 | 卖家选定某条意向、双方开始线下协商的动作；**此动作使商品进入「已冻结」状态** |
| 交易冻结 | 因「进入交易」而产生的冻结。与「手动冻结」共用「已冻结」状态，但**冻结来源**不同 |
| 手动冻结 | 卖家在后台主动冻结商品（**可以队列非空**） |
| 手动解冻 | 卖家把**手动冻结**的商品恢复在售；**交易冻结的商品禁用此操作** |
| 冻结来源 | 商品处于「已冻结」时记录其成因：**交易冻结**（进入交易时自动产生，禁止手动解冻，只能走「标记交易结果」结束）或**手动冻结**（卖家主动冻结，可手动解冻）。**该字段是实现解冻禁用逻辑的前提** |
| 手动下架 | 卖家把**在售且队列为空**的商品撤下并归档（**开发方新增需求**，业务方原始需求中无此项） |
| 下架 | 商品的终态：被撤下并进入历史记录，永久不可再售 |
| 当前商品 | 处于「在售」或「已冻结」的那一件商品，全局至多 1 件（`BR-11`）。买家端首页展示的即它 |
| 单一商品槽位 | 买家端的设计前提：任一时刻只对外呈现「当前商品」，因此买家端 **URL 不含商品 ID**，也**不存在「旧链接」问题** |
| 重新排队 | 交易失败后，卖家裁决把该买家意向**复用原记录**、序号刷新至队尾，继续排队 |
| 作废 | 交易失败后，卖家裁决把该买家意向置为终态「交易失败」 |
| 终态 | 意向的不可再变状态：交易成功 / 交易失败 / 已撤销。**「重新排队」不是终态** |
| 交易流水 | 「意向交易流水」的简称：每条意向的**每一次**交易结果的追加记录（含开始时间、结束时间、结果、失败类型与失败备注）。流水**只追加、不修改、不删除**，用于满足「历史中每次失败都能查到」的要求 |
| 静默买家 | 指「在队列中排队、但自己无从得知」的买家。本系统通过「重新排队不产生终态、口令码保持有效」规避该问题（见 `GAP-01`） |
