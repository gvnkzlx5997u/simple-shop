## 11.1 本章说明

| 项 | 内容 |
| --- | --- |
| **目的** | 定义**卖家端**前后端分离所需的**完整接口契约**：接口清单、每个接口的入参与出参、错误码，以及**错误码与提示文案的对照表**。该契约是卖家端（Vue）开发的**必要输入**，不可省略 |
| **为什么需要本章** | `C-06` 决定卖家端为 **Vue 客户端渲染**，`A-01` 据此要求**必须产出完整接口契约**。若只写页面不写契约，前端无法开工 |
| **买家端的处理** | 按 **`A-02`**，买家端为**服务端渲染**，**不出接口文档、出页面需求**（见第 10 章）。本章仅在 §11.4 列出买家端的**页面端点与提交点**供开发对齐，**它不构成 REST 契约** |
| **与第 9 章的关系** | 接口的字段**取自第 9 章数据字典**（`9-E` 命名规范）；**接口层不得引入本章与第 9 章未登记的持久化字段** |
| **与第 10 章的关系** | 第 10 章写页面**需要什么数据**，本章写这些数据**通过哪些接口取得**。每个接口须能回溯到 `P10-xx` 与 `FR-xx` |
| **与第 8 章的关系** | 接口的前置条件与拒绝规则由 `BR`／`INV` 决定；服务端**必须独立校验**，不得仅依赖页面禁用（`S10-07`、`G6-02`） |
| **编号口径** | 接口编号 `I11-01` ~ `I11-16`｜错误码**五位数分段**（§11.3.4）｜买家端业务结果码 `B11-xx`（§11.6.2）。**均以章号限定作用域** |
| **本章不做什么** | ① 不定义数据库表结构（第 9 章）；② 不定义页面元素与文案正文（第 10 章，本章只**引用**其 `M10-xx` 编号）；③ 不定义前端组件结构；④ 不规定具体序列化库与框架 |

## 11.2 接口形态总览

### 11.2.1 两端形态的差异（**本章最重要的口径**）

| 端 | 渲染方式 | 是否有接口契约 | 本章处理 |
| --- | --- | --- | --- |
| **买家端** | 服务端渲染（JSP） | **无**（`A-02`） | 仅列**页面端点**（§11.4），**不写 REST 契约** |
| **卖家端** | 客户端渲染（Vue） | **有，且必须完整**（`A-01`） | §11.5 **完整契约** |

> **⚠️ 这是本章与其他章节最容易被问到的分界点**：买家端之所以没有接口，是因为**它由服务端直接渲染页面**，页面与数据在服务端一起产出，前端无需再调接口；**不是**因为买家端功能简单。
>
> **为什么仍分两组呈现**：**买家端组**见 §11.4（**页面端点，非契约**）、**卖家端组**见 §11.5（**完整 REST 契约**）。差异仅在于：因 `A-02` 已判定买家端不出接口文档，**买家端组不以 REST 契约形式展开**，只列端点供服务端开发与页面开发对齐 URL。**这一点答辩时须主动说明。**

## 11.3 通用约定

### 11.3.1 基础约定

| 项 | 约定 | 依据 |
| --- | --- | --- |
| **协议** | HTTP／HTTPS | — |
| **请求／响应体** | 除图片上传外，一律 `application/json; charset=utf-8` | — |
| **字符集** | UTF-8；仅简体中文一种语言，不做多语言 | `NFR-19` |
| **字段命名** | **小写下划线 `snake_case`**，与第 9 章数据字典**完全一致** | `9-E` |
| **时间格式** | **ISO 8601、UTC**，形如 `2026-10-05T12:34:56Z`；**服务端不下发本地时间**，前端按东八区展示 | `C-10`、`C-11`、`DEC-27` |
| **金额格式** | `price` 以**字符串**下发（如 `"1234.00"`），**两位小数**；避免二进制浮点误差 | `C-12`、`DEC-21` |
| **枚举取值** | 一律使用第 9 章 §9.9 规定的**小写英文代码**（如 `on_sale`、`queued`），**不下发中文** | `9-Q` |
| **分页** | 请求 `page`（从 1 起）、`page_size`；响应含 `total`、`page`、`page_size` | `DEC-29` |
| **空值** | 可选字段无值时返回 `null`，**不省略键** | — |

### 11.3.2 鉴权与会话

| 项 | 约定 | 依据 |
| --- | --- | --- |
| **鉴权方式** | 登录成功返回 `token`；后续请求置于请求头 `Authorization: Bearer <token>` | `FR-01` |
| **会话机制** | **session + token**，**30 分钟无操作自动失效** | `DEC-13`、`NFR-04`、`C-07` |
| **失效响应** | token 缺失、无效或超时 → `HTTP 401` + 业务码 `10002`，前端跳转 `P10-05` | `P10-05` 状态表现 |
| **改密联动** | 修改密码成功后，**该账号的**全部**会话立即失效**，当前 token 亦失效 | `DEC-17`、`FR-02` |
| **登录限制** | 登录接口**不做失败次数限制**、**不做图形验证码**（已接受的风险，见第 12 章） | `DEC-25`、`DEC-26` |
| **买家端** | **不需要鉴权**（无账号体系）；其凭证为口令码，仅用于买家端页面，**不产生 seller 侧 token** | `O-01`、`BR-32` |

### 11.3.3 统一响应结构

**成功（`code = 0`）**

```json
{
  "code": 0,
  "message": "ok",
  "data": { }
}
```

**业务失败（`code` 非 0）**

```json
{
  "code": 20004,
  "message": "队列非空，无法下架",
  "data": null
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | int | **0 = 成功**；非 0 = 业务错误码（§11.3.4） |
| `message` | string | 服务端调试用简短描述；**前端不得直接展示**——界面文案统一取第 10 章《提示文案表》（`UX-07`、`NFR-09`） |
| `data` | object／array／null | 业务数据；无数据时为 `null` |

> **⚠️ 重要**：`message` 仅供日志与排查，**不作为界面文案**。前端须**按 `code` 映射到 `M10-xx`** 文案——这是保证「文案一致性」（`UX-07`）的关键机制。

### 11.3.4 HTTP 状态码使用规则

| HTTP | 使用场景 | 是否携带业务 `code` |
| --- | --- | --- |
| **200** | 请求已被服务端正常处理——**业务成功与业务规则拒绝（如队列非空）均返回 200** | 是（以 `code` 区分） |
| **400** | 请求报文本身不合法（JSON 解析失败、必填字段缺失、**参数格式错误**） | 是 |
| **401** | 未携带 token／token 无效／会话超时 | 是 |
| **403** | 已认证但无权访问该资源 | 是 |
| **404** | 路径不存在，或所查资源不存在（如历史商品 ID 无对应记录） | 是 |
| **500** | 服务端内部错误 | 否（返回通用错误结构） |

> **设计取舍说明**：业务规则拒绝（「队列非空」「商品非在售」）**使用 200 而非 4xx**——因为这类结果是**业务语义的正常分支**，不是传输或协议错误；用 200 + 业务码可使前端统一在 `code` 分支处理，避免与网络异常混淆。

### 11.3.5 错误码分段规则

| 分段 | 范围 | 含义 | 对应页面 |
| --- | --- | --- | --- |
| `0` | `0` | 成功 | — |
| `1xxxx` | `10001` ~ `19999` | **认证与会话** | `P10-05`、`P10-10` |
| `2xxxx` | `20001` ~ `29999` | **商品**（发布、冻结、解冻、下架、字段校验、**历史商品查询**） | `P10-06` ~ `P10-09` |
| `3xxxx` | `30001` ~ `39999` | **意向与交易**（名单、进入交易、标记结果、队列容量） | `P10-07` |
| `4xxxx` | `40001` ~ `49999` | **口令码** | `P10-04`、`P10-07` |
| `5xxxx` | `50001` ~ `59999` | **通用请求**（限流、参数、服务端） | 全部 |

> **编号约定**：分段的首位数字表示**业务域**，后四位为域内顺序号。**新增错误码须落在所属域内**，不得跨域占用。

## 11.4 买家端端点（**非契约**，仅供开发对齐）

> **⚠️ 本节不是接口契约。** 按 `A-02`，买家端为**服务端渲染**，交付物是 **JSP 页面**而非接口。本节列出**页面端点与表单提交点**，目的是让服务端开发与页面开发对齐 URL，**不要求前端（无需前端）调用**。
> 页面构成详见第 10 章 §10.3。

| 编号 | 端点 | 方法 | 路径 | 对应页面 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `B11-01` | 当前商品页 | `GET` | `/` | `P10-01` | **URL 无参数**（`A-03`、`S10-01`） |
| `B11-02` | 提交表单页 | `GET` | `/intent/new` | `P10-02` | 仅当商品为 `on_sale` 时可进入 |
| `B11-03` | 提交意向 | `POST` | `/intent` | `P10-02` → `P10-03` | 表单提交（非 JSON）；成功后在服务端渲染成功页并下发口令码 |
| `B11-04` | 口令码查询页 | `GET` | `/query` | `P10-04` | — |
| `B11-05` | 查询意向 | `POST` | `/query` | `P10-04` | 提交口令码，按三态返回结果 |
| `B11-06` | 修改姓名／电话 | `POST` | `/query/update` | `P10-04` | **不影响位次**（`queue_order` 不变） |
| `B11-07` | 撤销意向 | `POST` | `/query/revoke` | `P10-04` | **仅 `queued` 可撤销**（`IS-03`） |

> **⚠️ 三条口径**
> ① 所有路径**均不含商品 ID**（`A-03`）；
> ② 提交成功后**不得通过 URL 直接访问成功页**（口令码仅展示一次，`K5-02`）——`B11-03` 成功后应使用**服务端转发**（forward），而非重定向；
> ③ 买家端的处理结果**不用 HTTP 业务码**，由服务端**直接选择提示文案**（对照见 §11.6.2）。

## 11.5 卖家端接口明细（`I11-01` ~ `I11-16`）

> **通用说明**
> ① 除 `I11-01` 外，**全部接口须携带 `Authorization: Bearer <token>`**；
> ② 下表「入参」「出参」的字段名**与第 9 章数据字典一致**；
> ③ 错误码的**界面文案**统一取第 10 章《提示文案表》，本处以 `M10-xx` 指代；
> ④ 所有写操作**必须服务端独立校验前置条件**，不得仅依赖页面禁用（`G6-02`）。

### `I11-01` 卖家登录

**`POST /api/seller/session`**　｜　鉴权：**不需要**　｜　需求：`FR-01`　｜　页面：`P10-05`

| 入参 | 类型 | 必填 | 校验 |
| --- | --- | --- | --- |
| `account` | string | 是 | 非空，≤50 字符 |
| `password` | string | 是 | 非空 |

| 出参 `data` | 类型 | 说明 |
| --- | --- | --- |
| `token` | string | 会话令牌 |
| `expire_at` | string | 会话过期时间（UTC）；30 分钟无操作后失效 |

| 错误码 | 场景 | 界面文案 |
| --- | --- | --- |
| `10001` | 账号或密码错误 | `M10-23`（**统一提示，不区分账号／密码错误**） |
| `50002` | 参数缺失或为空 | 就地提示 |

> 登录**不做失败次数限制**（`DEC-25`）、**不做图形验证码**（`DEC-26`）；**不提供**找回／重置密码（`DEC-06`）。

### `I11-02` 退出登录

**`DELETE /api/seller/session`**　｜　鉴权：需要　｜　需求：`FR-01`　｜　页面：—

- **入参**：无（token 自请求头解析）
- **出参 `data`**：`null`
- **错误码**：`10002` 会话已失效

> **页面说明**：退出登录为**导航动作**（`P10-07` 导航区触发），**无独立页面**，故 §11.7.3 的「页面 → 接口」对照表中不单列——与 `FR-21`（否定性约束无页面）同类处理，**不属漏项**。

### `I11-03` 修改密码

**`PUT /api/seller/account/password`**　｜　鉴权：需要　｜　需求：`FR-02`　｜　页面：`P10-10`

| 入参 | 类型 | 必填 | 校验 |
| --- | --- | --- | --- |
| `old_password` | string | 是 | 非空 |
| `new_password` | string | 是 | **≥8 位**（`C-17`） |

- **出参 `data`**：`null`
- **副作用**：成功后**该账号全部会话立即失效**（`DEC-17`），前端须跳转 `P10-05`

| 错误码 | 场景 | 界面文案 |
| --- | --- | --- |
| `10003` | 原密码不正确 | `M10-34` |
| `10004` | 新密码长度不足 8 位 | 就地提示 |
| `50002` | 参数缺失 | 就地提示 |

### `I11-04` 查询当前商品

**`GET /api/seller/product`**　｜　鉴权：需要　｜　需求：`FR-04`　｜　页面：`P10-07`

- **入参**：无
- **出参 `data`**（无当前商品时 `data = null`，对应 `P10-07` 空态）

| 出参 `data` | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 商品 ID（前缀 `G`） |
| `name` | string | 名称 |
| `description` | string | 描述（**已转义**，`C-15`） |
| `pic_url` | string／null | 图片相对路径 |
| `price` | string | 两位小数 |
| `status` | string | `on_sale`／`frozen` |
| `freeze_by` | string／null | `manual`／`trade`；`on_sale` 时为 `null` |
| `create_at` | string | 发布时间（UTC） |
| `trade_start` | string／null | 交易开始时间；**仅内部使用，界面不展示**（澄清 Q22） |

> **`freeze_by` 必须下发**：`P10-07` 依赖该字段判断「解冻」按钮是否可用（`FR-04` 注、`PS-06`）。
> **错误码**：`50001` 请求过于频繁。

### `I11-05` 上传商品图片

**`POST /api/seller/product/image`**　｜　鉴权：需要　｜　需求：`FR-03`　｜　页面：`P10-06`

| 入参 | 类型 | 必填 | 校验 |
| --- | --- | --- | --- |
| `file` | file（`multipart/form-data`） | 是 | **JPG／PNG**；**≤5MB**；最多 1 张（`C-14`） |

| 出参 `data` | 类型 | 说明 |
| --- | --- | --- |
| `pic_url` | string | **服务端生成的相对路径**，供 `I11-06` 使用；**不采用用户原始文件名** |

| 错误码 | 场景 | 界面文案 |
| --- | --- | --- |
| `20009` | 格式不支持或超过 5MB | `M10-31` |
| `50001` | 请求过于频繁 | 就地提示 |

> **双重校验**：前端预校验 + 后端校验（`NFR-11`）。图片存**服务器文件系统**，数据库只存路径（`DEC-09`、`DEC-34`）。

### `I11-06` 发布商品

**`POST /api/seller/product`**　｜　鉴权：需要　｜　需求：`FR-03`　｜　页面：`P10-06`

### `I11-11` 进入交易

**`POST /api/seller/intention/trade`**　｜　鉴权：需要　｜　需求：`FR-07`　｜　迁移：`PS-01`、`IS-02`　｜　页面：`P10-07`

| 入参 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `intention_id` | string | 是 | 目标意向 ID |

- **出参 `data`**：`null`
- **副作用**：商品 `status → frozen`、`freeze_by → trade`；该意向 `status → trading`；写 `trade_start`；其余 `queued` 意向**保持不变**（`BR-01`）

| 错误码 | 场景 | 界面文案 |

| `20003` | 商品非在售 | 按钮不可用 |

| `30003` | 目标意向状态非 `queued` | 拒绝 |

### `I11-12` 标记交易成功

**`POST /api/seller/intention/success`**　｜　鉴权：需要　｜　需求：`FR-09`　｜　迁移：`PS-03`、`IS-04`、`IS-05`　｜　页面：`P10-07`

| 入参 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `intention_id` | string | 是 | 处于 `trading` 的意向 ID |

- **出参 `data`**：`null`
- **执行顺序（`BR-03`，不可调换）**：
  1. 其余 `queued` 意向 → `failed`，`fail_type = sold_out`（`IS-04`）
  2. 本次意向 → `succeeded`（`IS-05`）
  3. 商品 → `off_sale`，写 `trade_end`、`result = sold`，**归档入历史**
- **副作用**：各意向口令码随终态而**失效**（`BR-26`）；为本次及此前每次失败**追加流水**（第 9 章 §9.7）

| 错误码 | 场景 | 界面文案 |
| --- | --- | --- |
| `20004` | 商品非已冻结 | 按钮不可用 |
| `30003` | 目标意向非 `trading` | 拒绝 |
| `30005` | 归档前置校验失败（若存在非终态意向，`INV-05`） | 服务端回滚并报错 |

> **⚠️ 本接口是全系统影响面最大的写操作**（一次调用改变其余全部意向 + 本次意向 + 商品状态）——**必须整体置于一个事务内**，保证 `INV-05`、`INV-06` 成立。

### `I11-13` 标记交易失败

**`POST /api/seller/intention/failure`**　｜　鉴权：需要　｜　需求：`FR-10`　｜　迁移：`PS-04`、`IS-06`／`IS-07`　｜　页面：`P10-07`

| 入参 | 类型 | 必填 | 校验 |
| --- | --- | --- | --- |
| `intention_id` | string | 是 | 处于 `trading` 的意向 ID |
| `disposal` | string | 是 | **枚举**：`voided`（作废）／`requeued`（重新排队） |
| `fail_reason` | string | 否 | **≤300 字符**；允许换行；**买家不可见** |

- **出参 `data`**：`null`
- **副作用**：
  - 商品 `status → on_sale`（`PS-04`）
  - `disposal = voided` → 该意向 `failed`，`fail_type = voided`（`IS-06`）
  - `disposal = requeued` → 该意向回 `queued`，`queue_order` **刷新至队尾**，`create_at` **不变**，**口令码保持有效**（`IS-07`、`BR-27`）
  - 其余 `queued` 意向状态不变、位次**依次前移**（`BR-04`）
  - **无论哪种裁决，均追加一条流水**（第 9 章 §9.7.2、已决 `9-D`）

| 错误码 | 场景 | 界面文案 |
| --- | --- | --- |
| `20004` | 商品非已冻结 | 按钮不可用 |
| `30003` | 目标意向非 `trading` | 拒绝 |
| `30006` | `disposal` 取值非法 | 就地提示 |
| `30007` | `fail_reason` 超长 | 就地提示 |

> **⚠️ 三点必须写清（答辩高频）**
> ① **「重新排队」不产生终态，口令码保持有效**（`BR-27`、`INV-08`）——这是 `GAP-01`（静默买家）消解的原因；
> ② **`queue_order` 刷新、`create_at` 保留**——两个字段各司其职（`DEC-15`）；
> ③ **作废与重新排队都是卖家裁决权**，买家侧只有「撤销」（`BR-06`、`BR-18`）。

### `I11-15` 历史商品列表

### `I11-16` 历史商品详情

**`GET /api/seller/history/products/{id}`**　｜　鉴权：需要　｜　需求：`FR-11`、`FR-08`　｜　页面：`P10-09`

- **出参 `data`**：

> 第 9 章 v1.1（已决 `9-S`）已从历史意向表删除该两列：`queue_order` 是**过程性辅助数据**（队列已清空，位次无意义），`token` 在归档时**已失效**且 `FR-24`／`NFR-16` 明确「对终态意向不返回可用口令码」。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `trade_start`／`trade_end` | string | 该次交易的开始／结束时间 |
| `result` | string | `sold`／`failed`（流水级，`succeeded` 用 `sold`） |
| `fail_type`／`fail_reason` | string／null | 该次的失败类型／备注 |

| 错误码 | 场景 | 界面文案 |
| --- | --- | --- |
| `20011` | 历史商品 ID 不存在（HTTP 404） | 错误态提示 |

> **⚠️ `trades[]` 是本接口的关键字段**：业务方要求「一个商品前两次交易失败、第三次才卖掉，这一路的过程在历史里都查得到」（澄清 Q15）。**若只返回最终结果，即不满足业务方要求**（第 9 章 §9.7.3）。

## 11.9 决策与开放事项

### 11.9.1 已决事项（编制过程中确定）

| 编号 | 事项 | 结论 | 落实位置 |
| --- | --- | --- | --- |
| `11-A` | 买家端是否产出接口文档 | **不产出**（依 `A-02`）。仅列**页面端点**供对齐，明确标注「非契约」 | §11.2.1、§11.4 |
| `11-B` | 业务规则拒绝使用 HTTP 4xx 还是 200 | **统一 200 + 业务码**——业务拒绝属**业务语义的正常分支**，非传输错误；便于前端统一在 `code` 分支处理 | §11.3.4 |
| `11-C` | 图片上传是独立接口还是随发布一并提交 | **独立接口** `I11-05`：便于 `P10-06` 做**图片本地预览**，且先后端校验通过再提交表单 | §11.2.2、§11.5 |
| `11-D` | 意向名单是否下发口令码 | **不下发**：口令码为敏感字段，**须经 `I11-14` 按意向单独查询**，避免名单接口批量泄露 | §11.5 `I11-10` |
| `11-E` | 响应结构采用 `code` 还是 HTTP 状态码单轨 | **双轨**：HTTP 表达传输层结果，`code` 表达业务结果；`message` **仅供调试，前端不得展示** | §11.3.3 |
| `11-F` | 金额字段的传输类型 | **字符串**（两位小数），避免二进制浮点误差 | §11.3.1 |
| `11-G` | 历史详情是否返回每一次交易流水 | **返回**（`trades[]`）——业务方明确要求「每次失败都能查到」（澄清 Q15）；只返最终结果即不满足 | §11.5 `I11-16` |
| **`11-H`** | 历史意向名单 `intentions[]` 的**排序字段**（v1.1 新增） | **按 `create_at`（意向提交时间）升序**。原契约未规定排序字段；因第 9 章 v1.1 已从历史意向表**删除 `queue_order`**（已决 `9-S`），故改以提交时间为排序键——与 `BR-21`「历史名单展示意向提交时间」的口径一致 | §11.5 `I11-16` |
| **`11-I`** | 历史详情是否返回 `queue_order` 与 `token`（v1.1 新增） | **均不返回**。第 9 章 v1.1 已从历史意向表删除该两列：`queue_order` 为**过程性辅助数据**（队列已清空、位次无意义），`token` 在归档时**已失效**且 `NFR-16` 明确「对终态意向不返回可用口令码」。即**历史详情不提供口令码查看能力** | §11.5 `I11-16`；已决 `9-S` |
