# 需求澄清记录

针对基线需求，对用户进行提问，得到了以下需求澄清记录

**问题1**

- 问：买家买的时候不用登录，该如何再次查看之前下单的商品状态和交易进度
- 答：你这一下又点到我没说全的地方了。
  买家虽然不登录，但每次提交购买意向后，系统会当场生成一个唯一的口令码，直接显示在提交成功的页面上，让他自己保存好。
  之后他就凭这个口令码来查自己的意向——现在排到第几位、有没有进入交易，都能查到；还能凭它改自己留的姓名、电话，或者撤销意向。
  不过这个口令码只在交易结束（成功或失败）或商品下架后失效，之后就不能再用来查了。

**问题2**

- 问：卖家在发布商品后且商品未冻结时，能不能修改这个商品的信息
- 答：不能。这个版本没有「修改已发布商品信息」的功能——商品发布后，名称、描述、图片、价格这些信息就固定下来了。卖家后台对商品能做的只有发布、冻结/解冻、标记交易成功或失败，没有编辑入口。

**问题3**

- 问：两个买家几乎同时提交购买意向时应该怎样处理？是否只接受第一条并立即冻结商品？其他买家应看到什么结果？冻结期间商品详情是否仍可浏览？
- 答：同时提交这种，谁先提交算谁在前，系统按提交时间排个先后——先到先得。两个意向都收进来，最早那个先进交易，后面的排队等着，前面要是没谈成，后面的再依次顶上来。
  不是谁一提交就马上冻结。提交只是排上队了；真正冻结，是我跟某一个买家开始谈交易的时候才冻。冻上之后，后面的人就再也提交不了意向了（页面上会提示「商品交易中」）。
  排后面的买家，能凭口令码看到自己现在排第几位。
  冻结期间，商品详情还是能看的，就是不能买、也不能再提交意向了。

**问题4**

- 问：冻结后的所有解除方式是什么？请分别说明线下交易成功、交易失败、买家反悔、卖家主动冻结和卖家解除冻结的处理规则。是否需要超时自动恢复在售？
- 答：商品从「冻结」变出去的路子，就这几条：
  **线下交易成功**：我后台标记「交易成功」，商品从冻结直接「下架」，永久撤下来，进历史记录。
  **交易失败**：我后台标记「交易失败」，商品从冻结恢复「在售」，重新上线，还能再收意向；后面要是有排队的人，按顺序顶上来。
  **买家反悔**：买家反悔，对我来说就是这笔交易黄了，等同交易失败——我标记失败，商品恢复在售。（买家自己那边，还没轮到交易、还在排队的时候，他能凭口令码主动撤销意向，但那只是退出队列，跟解冻不是一回事。）
  **卖家主动冻结**：这条不是解冻，是「进入冻结」——我可以在后台手动把在售商品冻上，跟自动冻结是同一个「已冻结」状态。
  **卖家手动解冻**：我也可以在后台手动解冻，解冻后商品恢复在售。
  **超时自动恢复**：不需要。系统不会到点自己恢复在售，恢复在售要么我标记交易失败、要么我手动解冻，都得我动手。

**问题5**

- 问：买家无需注册时，提交购买意向必须填写哪些信息？
  是否只需姓名和联系电话？买家提交后是否需要自行查询进度或取消意向，还是统一由卖家联系和处理？
- 答：
  **填什么**：提交意向就填两样必填的——姓名、联系电话。别的不用，不注册、不设账号。
  - 提交之后：不是全由我联系。提交成功那一下，系统会给他一个口令码，他凭这个码能自己：
  - 查进度（排到第几位、进没进交易）
    改自己的信息（姓名、电话都能改，改了不影响排队位次）
  - 撤销意向（撤销了就退出队列）
    当然我后台也能看到他填的姓名电话、主动联系他，但查询和撤销这些，买家自己就能办。

**问题6**

- 问：一位买家交易成功、商品下架后，其余排队意向显示什么最终结果？他们还能凭口令码查到这个结果吗？
- 答：商品交易成功、一下架，其余排队的人就算没轮上、没成交了，他们的意向到此结束——商品已经卖给先到的那个人了。
  **口令码**：失效了。商品一下架，所有口令码就作废，他们不能再凭码查到任何结果（包括"没成交"这个结果）。
  **不过**：他们填的姓名、电话这些，还留在我的后台历史记录里——每个商品的意向购买人名单都存着，含提交时间和对应结果，只是买家自己查不到了，我后台能翻到。

**问题7**

- 问：卖家在发布商品后且商品未冻结时，能不能修改这个商品的信息
- 答：不能。这个版本没有「修改已发布商品信息」的功能——商品发布后，名称、描述、图片、价格这些信息就固定下来了。卖家后台对商品能做的只有发布、冻结/解冻、标记交易成功或失败，没有编辑入口。

**问题8**

- 问：商品进入交易是由买家确认的吗？买家排队时，凭口令码，除了查询位次，修改信息，退出队列，还能做什么？
- 答：
  先答第一个：不是买家确认的。买家提交意向之后就排队等着，没有「确认进入交易」这一步。进入交易是我（卖家）这边发起的。
  第二个：凭口令码能做的就这三件，没有别的了——
  **查询状态**：不只是排队位次，还包括「有没有已经进入交易」；
  **修改信息**：姓名、联系电话两项都能改，改完不重新排队；
  **撤销意向**：就是你理解的退出队列，撤了之后后面的位次往前移。
  除此之外，口令码没有别的用处。

**问题9**

- 问：所以作废意向和重新排队是由买家决定的，那么买家查看订单的时候是否需要设置这两个选项？
- 答：等等，这里你理解反了。「作废」还是「重新排队」不是买家决定的，是卖家在后台确认的——交易失败后，由我（卖家）来决定这个买家的意向是作废掉，还是重新排回队里。
  买家那边只有他自己能主动做的操作：撤销。他拿口令码进来，能做的是查位次、改姓名电话、撤销自己的意向。撤销是他自愿退出；「作废/重新排队」是交易失败后由我处理，两者不是一回事。
  所以买家查看自己意向时，选项只有一个「撤销」，不存在「作废」或「重新排队」这两个按钮。

**问题10**

- 问：买家可以在交易的时候撤销吗？
- 答：能撤销的是「购买意向」，也就是还在排队、没真正进入交易的时候可以撤，撤了就从队列里移除，后面的人往前补。
  但一旦已经进入交易、商品冻结了，就没有买家撤销这回事了——这笔交易最后是成功还是失败，由我在后台标记。

**问题11**

- 问：卖家拒绝了当前买家，是否可以选择把当前买家重新排到队尾？
- 答：交易失败之后，我可以选把这个买家的意向直接「作废」，也可以让他「重新排队」，这两个由我在后台确认。作废就是把他的意向直接删掉；重新排队就让他排到队尾，前面排着的人依次往前补。

**问题12**

- 问：卖家页面具体长什么样，有哪些数据？
- 答：我的卖家后台大概就这几个功能入口：
  **发布商品**：填名称、描述、图片、价格。
  **查看历史商品**：能看到卖掉的、交易失败过的商品，每条记录有名称、描述、图片、价格、发布时间、交易结果、交易时间，按时间倒序排，能翻页。
  **查看意向购买人**：对交易中的商品，能看到所有想买的人的姓名、联系电话和提交意向的时间。
  冻结/解冻商品：对在售或冻结的商品切换状态。
  **修改密码**：改我自己的登录密码。
  历史商品点进去，还能看到每个商品的意向购买人列表，里面有姓名、联系电话、提交时间、对应的交易结果。

**问题13**

- 问：商品简介中可以嵌入图片吗？
- 答：图片不是嵌在简介文字里的，是单独一个图片字段。商品信息就是名称、描述、图片、价格四样分开的东西——简介（描述）是纯文字，可以留空；图片单独传，一个商品最多放一张主图，JPG 或 PNG 格式，单张别超过 5MB。

**问题14**

- 问：已经有买家进入交易时，如果卖家点“手动解冻”，这位买家的意向会自动变成交易失败，还是必须先由卖家标记交易失败？
- 答：这俩不是一回事，手动解冻不会自动把那位买家的意向判成失败。
  **手动解冻**：只是把商品从「冻结」放回「在售」，就动了商品这一个状态，不碰买家的意向。
  **标记交易失败**：这才是正式结束跟某位买家的交易——那时候我会确认这位买家的意向是作废还是重新排队，商品同时恢复在售。
  所以真在跟人谈着的时候想结束，走「标记交易失败」；手动解冻主要是**我自己冻了商品**（没人在谈）之后想解开用的。

**问题15**

- 问：商品可能会经历多次交易失败后才交易成功并下架，在历史商品中需不需要查看这些失败记录，还是只需要一个最终结果？
- 答：需要看失败记录，不是只看一个最终结果。
  商品进了历史之后，除了商品本身有个「最终结果」（最后到底是成功下架还是失败收场），我还能点进去看它的意向购买人列表——里面每个买家都带着自己那次的交易结果。
  所以一个商品前两次交易失败、第三次才卖掉，这一路的过程在历史里都查得到，不是只留一个「成功」了事。

**问题16**

- 问：正在与买家交易时，后台是否允许点击“手动解冻”？如果允许，商品变回在售、买家意向却仍是交易中，此时能否接收新的意向？
- 答：能不能点：能。手动解冻就是后台一个按钮，商品处在「已冻结」状态时都能点——手动冻的和自动冻的共用一个状态，系统分不开，也没禁止在交易中点解冻。
  解冻之后：商品回到「在售」，但那位买家的意向没被动，还是「交易中」挂着——这就成了个说不清的状态了。
  能不能收新意向：能。按规则只有「冻结」期间才不收新意向，商品一回到在售，新意向就能提交。结果就是一件商品在售、还能收新意向，可原来的买家还卡在「交易中」——你提的这个确实是个漏洞，我之前没细想。
  所以正经做法还是走「标记交易结果」来结束交易，别在谈着的时候直接点解冻。

**问题17**

- 问：是否修正手动解冻漏洞：交易中禁止手动解冻，要求卖家先标记交易结果。
- 答：对，这么改合理。交易中的商品（自动冻的）就不能直接点解冻，要结束交易就走「标记交易结果」（成功或失败）。手动解冻只留给我自己手动冻的商品——没人在谈、我想解开就用它。
  这样就不会再出现「商品在售、买家却还卡在交易中」那种乱状态了。

**问题18**

- 问：卖家手动冻结商品，手动下架商品的前置条件分别是什么，在售即可，还是队列必须为空？若手动下架只需在售即可，队列中的意向怎么处理，怎么通知买家？
- 答：**手动冻结**：商品在售就能冻，不要求队列清空。冻了之后就不再收新的购买意向（页面提示「交易中」）。
  **手动下架**：这个我其实没细想。需求里只提了一句——一次只能卖一件，要发新商品，得先把当前的交易做完，或者手动下架。但「手动下架」的前置条件、要不要等队列清空、队列里的意向怎么处理，这些都没写死，我也没有明确的想法。
  **通知买家**：系统里没有主动通知买家这一说。买家都是拿口令码自己查状态的，不会收到什么推送。

**问题19**

- 问：已下架商品（交易成功、手动下架），由于口令码失效，在买家这一侧如何查询？假设买家提交了购买意向，还没输过口令码，商品就被买走了/下架了，此时他再去输口令码会发生什么？
- 答：已下架商品在买家侧怎么查？ 查不了。已售/已下架的商品本来就不对买家展示，只有我后台能看；口令码在商品下架后也失效了。所以买家那边没有任何查询途径。
  没输过口令码、商品就被买走/下架了，再输会怎样？ 输进去也没用——口令码已经失效，系统不会再让他查询或修改，只会提示这个口令码已经不能用（失效）了。
  顺带一句：口令码在提交成功页面只展示一次，如果买家当时没保存，后面连码都没有，就更谈不上查询了。

**问题20**

- 问：口令码的实现方式有没有要求，例如：有没有长度限制？另外，买家交易失败，但商品未下架，重新排队后，原口令码是否失效，此时的购买意向需要新建，还是通过更改原意向的排队次序实现？
- 答：口令码的实现方式：需求里没做要求，没有长度限制、也没有格式规定，只要求它是「唯一」的——每个意向一个独有的码。（顺带说下：「长度不少于 8 位」那条是我后台登录密码的要求，不是口令码。）
  交易失败后的口令码和意向：
  原口令码：失效。口令码在「交易结束（成功或失败）」后就失效了，这条是明确的。
  意向怎么处理：两种，由我在后台确认——「作废」或者「重新排队」。
  「重新排队」是新建意向还是改原意向位次：需求里没写死这个实现细节。但有一点是明确的——买家自己改信息不会改变排队位次、也不重新排队，所以买家没法自己改位次；重新排队是我在后台操作的。
- 追问：那么买家怎么知道重新排队后的新口令码，这好像只能由卖家在系统外通知他？
- 答：你抓到点子上了，这确实是个漏洞。
  系统里没有通知买家的机制，买家只能靠自己拿口令码查。旧码在交易失败后就失效了，重新排队后买家在系统里根本没法知道新码——只能我在系统外（打电话、当面）告诉他。
  这块我确实没想周全，你把它记下来。

**问题21**

- 问：发布商品时，图片是否必填？对于价格，有没有币种，精度限制；有没有数值限制（最大值/最小值，是否能为0）？对于名称和描述有没有长度限制？
- 答：图片：选填，不是必填。不传就显示一张占位图。要传的话，最多 1 张主图，JPG/PNG 都行，单张不超过 5MB（超了系统会提示）。
  价格：必填。币种是人民币（元），精度保留两位小数。数值必须大于 0——不能是 0，也不能是负数；上限没有规定。
  名称和描述：长度限制需求里没规定。名称是必填，描述是选填（可以为空）。

**问题22**

- 问：是否记录卖家点击「进入交易」的时间？历史商品、意向详情里展示哪个时间（交易开始，交易结束，或是两者都要展示）？重新排队后，历史意向里显示一条记录还是两条记录？
- 答：（1）会记。卖家一点「进入交易」，商品就自动冻结了，冻结属于关键操作，系统会留下时间戳——这个时间就是交易开始的时间。
  （2）展示上：历史商品里展示「发布时间」和「交易时间」，「交易时间」指的是交易出结果（也就是结束）的那个时间点，不是开始时间。交易开始（冻结）的时间系统是记了的，但历史商品列表里主要展示的是结束时间。意向详情（意向购买人列表）里展示的是「意向提交时间」和对应的交易结果，不单独展示交易开始/结束时间。
  （3）重新排队是同一条意向回到队列继续等，不会新生成一条记录。历史意向里显示一条，对应的是它最终的交易结果。

**问题23**

- 问：由于系统没有主动通知，买家侧的界面提示承担了全部沟通责任。问题一、以下哪些操作需要二次确认？1、提交购买意向前（回显姓名、电话）2、撤销意向前（提示不可恢复）3、修改姓名/电话前（提示不影响位次）4、离开提交成功页前（提醒已保存口令码）。问题二、交易流程如何告诉买家，一段说明文字还是单独一页「交易流程说明」？问题三、以下哪些关键状态需要提示买家？1、你当前排在第 N 位 2、商品交易中，暂停接收新意向 3、你已进入交易，请与卖家联系 4、口令码已失效 5、你的意向已撤销
- 答：（1）二次确认：需求里没规定这些操作要二次确认，这个交互细节你们设计时自己把握。我明确要求的就是第 4 点里那条——提交成功后口令码要直接展示、并提醒买家保存。其余（回显、撤销确认、修改前提示）需求层面都没定，你们按体验自己加，不强制。
  （2）交易流程：不需要单独说明页，也不需要写说明文字。买家的流程就一句话——看商品 → 提交意向（拿口令码）→ 凭码查状态，没别的要解释的。
  （3）状态提示：需要让买家看到的，需求里明确的是这几个——「商品交易中，暂停接收新意向」（页面提示）、「你当前排第 N 位」（凭口令码可查）、「是否已进入交易」（凭口令码可查）。至于「口令码已失效」「意向已撤销」这两个，机制需求里有（失效后不可查、撤销后移除），但要不要单独提示、怎么提示，需求里没细说，你们设计时自己定。

**问题24**

- 问：同一个电话号码，能否对同一件商品提交多条意向，买家提交后想改信息，是走「凭口令码修改」还是「再提交一次」？
- 答：这个版本不需要这种「按联系方式去重、覆盖合并」的机制。
  我现在的想法就是：每次提交都是一条独立的意向记录，一条就是一条，不会因为联系方式相同就自动合并覆盖。真要改自己的信息，有专门的通道（凭提交时拿到的凭证），不是靠「重复提交同名联系方式」去覆盖。
