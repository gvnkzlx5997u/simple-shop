## 3.1 技术栈

| 编号 | 约束项 | 结论 | 依据 |
| --- | --- | --- | --- |
| C-01 | 后端技术 | **SpringBoot** | `DEC-18` |
| C-02 | 数据库 | **MySQL** | `DEC-18` |
| C-03 | 应用形态 | **单体应用**，不使用微服务 | `DEC-18` |
| C-04 | 中间件 | **不使用缓存组件、不使用消息队列** | `DEC-18` |
| C-05 | 买家端前端 | **服务端渲染（JSP）**，配合移动端优先的响应式布局 | `DEC-18`、`DEC-20` |
| C-06 | 卖家端前端 | **客户端渲染（Vue）**，与后端前后端分离 | `DEC-18` |
| C-07 | 会话机制 | **session + token**；30 分钟无操作自动退出；日后有需要再考虑 JWT | `DEC-13` |
| C-08 | 图片存储 | **服务器文件系统**，数据库仅存路径 | `DEC-09` |
| C-09 | 界面语言 | **仅简体中文** | `DEC-28` |

## 3.2 架构形态

```

│                                                             │
│   ┌───────────────────────┐   ┌───────────────────────────┐ │
│   │   买家端（JSP / SSR）  │   │  卖家端接口（REST）        │ │
│   │   · 当前商品页（首页）  │   │  · 商品管理 / 意向管理     │ │
│   │   · 提交意向           │   │  · 交易结果登记            │ │
│   │   · 提交成功（口令码）  │   │  · 历史查询                │ │
│   │   · 口令码查询与操作    │   │  · 登录 / 改密             │ │
│   └───────────┬───────────┘   └────────────┬──────────────┘ │
```

### 3.2.2 架构约束带来的直接影响

| 编号 | 影响 | 说明 | 关联需求 |
| --- | --- | --- | --- |
| A-01 | **需定义卖家端接口契约** | 卖家端为前后端分离形态，必须产出完整的接口清单（入参、出参、错误码） | 第 11 章 |
| A-02 | **买家端不出接口文档，出页面需求** | 买家端为服务端渲染，交付物是 JSP 页面而非接口 | 第 10 章 |
| A-03 | **买家端 URL 不含商品 ID** | 因单一商品槽位设计（见第 2 章 B-02），买家端无需商品 ID 参数，也无需处理参数校验与越权访问 | `FR-19`、`DEC-38` |
| A-04 | **并发排序完全依赖数据库** | 无缓存、无队列组件，队列排序必须通过数据库的独立自增序号实现，并在提交事务内分配 | `NFR-01`、`DEC-10`、`DEC-15` |
| A-05 | **移动端优先的布局需在 JSP 层实现** | 买家端不引入前端框架，响应式布局需用原生 CSS 实现 | `NFR-10`、`DEC-20` |
| A-06 | **图片访问需处理文件路径** | 图片存文件系统，须定义访问路径规则与目录结构 | `NFR-11`、`DEC-09` |

## 3.3 数据与时间规范

| 编号 | 规范 | 内容 | 依据 |
| --- | --- | --- | --- |
| C-10 | 时间存储 | 统一以 **UTC** 存储 | `DEC-27` |
| C-11 | 时间展示 | 统一按**东八区（UTC+8）**展示 | `DEC-27` |
| C-12 | 金额精度 | 人民币（元），**两位小数**，取值范围 **0 < 价格 ≤ 999,999.99** | 澄清 Q21、`DEC-21` |
| C-13 | 文本长度 | 商品名称 **≤50 字符**；商品描述 **≤500 字符** | `DEC-22` |
| C-14 | 图片规格 | 最多 **1 张**主图；**JPG 或 PNG**；单张 **≤5MB**；**不生成缩略图** | 澄清 Q13、Q21、`DEC-34` |
| C-15 | 文本安全 | 商品描述为纯文本，须做 **XSS 防护**（输入校验 + 输出转义） | `DEC-22`、`NFR-20` |
| C-16 | 口令码格式 | **12 位大写字母 + 数字**（不排除易混字符 0/O/1/I） | `DEC-07` |
| C-17 | 卖家密码格式 | 长度 **≥8 位** | 澄清 Q20 |
| C-18 | 数据留存 | 业务数据（商品、意向、历史、流水）**永久保留**；操作日志保留 **3 个月** | `DEC-19`、`DEC-14` |

## 3.4 开放项

以下约束**尚未确定**，将登记入第 13 章附录。**不影响第 5 ~ 12 章的编写**，但会影响详细设计与部署。

| 编号 | 开放项 | 当前状态 | 建议决断时间 | 影响面 |
| --- | --- | --- | --- | --- |
| OPEN-01 | **系统部署形态**（单机 vs 容器化） | 开发方明确「有同时考虑单机部署和容器化的需求，现阶段暂缓」 | **详细设计阶段前，越早越好** | ① 若容器化，图片目录需挂载**持久卷**（关联 C-08）；② 若容器化**多实例**，session + token 的会话需共享存储——而 C-04 已排除缓存组件，**二者存在潜在张力**，届时需复核 C-07 与 C-04 |
| OPEN-02 | **数据备份与恢复策略** | 开发方暂缓 | 交付前 | 备份须**同时覆盖数据库与图片目录**（C-02、C-08、C-18）；**数据库侧须包含队列序号辅助表**（`simpleshop_queue_sequence`，见第 9 章 §9.3.1／§9.11，已决 `9-S`）——否则恢复后其 `current_value` 归零，会与库内既有 `queue_order` 冲突（唯一索引会直接报错，属**可发现**的失败，不会静默产生重复值） |
| OPEN-03 | **数据导出能力** | 开发方暂缓 | 可延至二期 | 非必需；与 C-18 的永久保留互补 |

> **提示**：OPEN-01 是三项中唯一可能**反向影响既有约束**的开放项。若最终选择容器化多实例部署，需回头复核 C-07（会话机制）与 C-04（无缓存组件）是否仍然成立。
