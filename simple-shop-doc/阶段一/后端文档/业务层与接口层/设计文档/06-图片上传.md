# 6. 图片上传（`I11-05`）

| 项 | 口径 | 依据 |
| --- | --- | --- |
| 存储位置 | **服务器文件系统**，配置化目录（`simple-shop.image.directory`） | `C-08`、`DEC-09` |
| 库内 | **只存相对路径**（`varchar(512)`），**不存二进制** | `NFR-11` |
| 校验 | **JPG / PNG**（**必须校验真实内容，不能只看扩展名或 `Content-Type`**——建议读文件魔数）；单张 **≤5MB** | `C-14`、`NFR-11` |
| 文件名 | **服务端生成**（如 `UUID + 规范化扩展名`），**不采用用户原始文件名** | 防路径穿越与覆盖 |
| 目录策略 | 按日期分子目录（如 `2026/10/`），便于运维；返回路径形如 `/images/2026/10/<uuid>.jpg` | — |
| 访问 | `WebMvcConfig` 把 `/images/**` 映射到该目录（`addResourceHandlers`） | `A-06` |
| 双重校验 | 前端预校验 + 后端独立校验；**必须验证「绕过前端直传 >5MB 仍被拒」** | `NFR-11` |
| 缩略图 | **不生成** | `DEC-34`、`R12-04` |
| 占位图 | 不传则买家端显示**占位图**（**本轮不做 JSP，占位图前端侧实现**；`pic_url` 允许为 `null`） | `C-14` |
| 失败 | `20009` / `M10-31` | `11.6.1` |

**`pic_url` 的回填校验（`I11-06`）**：`pic_url` 若传入，必须是**本服务生成过的合法相对路径**（正则限定为 `/images/yyyy/MM/<uuid>.<jpg|png>`，且文件确实存在）。**不得接受任意字符串**——否则前端可写任意值进库（`BR-15` 虽禁止修改，但首次发布仍可写入）。

> **`multipart` 配置**：`max-file-size: 5MB` 是 Spring 层的**软阈值**；超限时 Spring 会在进入 Controller **之前**抛 `MaxUploadSizeExceededException`，**必须在 `GlobalExceptionHandler` 中捕获**并映射为 `20009`，否则会变成 500。

> **⚠️⚠️ 但只做上面这一步是不够的：`20009` 会送不到客户端（S4 真实端口实测发现，已修）**
>
> **现象**：只配 `max-file-size` 时，上传 6MB 文件的真实结果是客户端收到
> `Unable to write data to the transport connection: 远程主机强迫关闭了一个现有的连接`
> ——**连接被直接断开，契约要求的 `20009` 与 `M10-31` 根本没有送达**。
>
> **原因**：Tomcat 在「读到超限」那一刻就抛 `SizeLimitExceededException`，但此时**请求体还剩一大截没读**。它必须先把这个尾巴读完（swallow）才能在同一连接上发响应；而 `max-swallow-size` **默认只有 2MB**，尾巴超过它就**直接断连**。所以异常处理写得再对，响应也发不出去。
>
> **影响**：恰好命中 `NFR-11` 的可测指标「绕过前端直传 >5MB **仍被拒绝并提示 `M10-31`**」与验收方式 `V-02`「必须包含绕过前端的负向调用」——前端只会显示一个网络错误，用户永远看不到「单张不超过 5MB」。
>
> **修复**（`application.yml`）：
> ```yaml
> server:
>   tomcat:
>     max-swallow-size: 10MB   # 默认 2MB 不够：必须 ≥ 要吞掉的请求体大小
> ```
> 取值 **10MB** 而非 `-1`（不限）：10MB 覆盖「略超 5MB」这一现实拒绝区间（前端自身限 5MB，绕过测试通常传 6MB 左右），使这些请求都拿到明确的 `20009`；而 `-1` 意味着任何超大请求都会把连接里的字节全读一遍，是一个白送给攻击者的资源消耗面。超过 10MB 的请求**仍会被拒绝**，只是以「断开连接」的形式——对只允许 5MB 的接口而言业务含义一致。
>
> **⚠️ 这条配置必须有测试守护**：它看起来像一条「无用配置」，极易被当成冗余删掉。而 `MockMvc` **结构上测不到**它（直接构造 `MockMultipartHttpRequest`，既不经过真实 multipart 解析器，也没有可断的连接）。故新增了真实容器用例 `SellerImageUploadContainerTest`（`webEnvironment = RANDOM_PORT`），并**实测验证过该用例在缺此配置时会失败**（见 §8.8 的「D-2」）。
