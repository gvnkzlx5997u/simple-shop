# 9. 实施步骤（建议顺序，每步可独立验证）

| 步 | 内容 | 产出与验证 |
| --- | --- | --- |
| **S0** | **基线确认**：`cd simple-shop/simple-shop-backend && mvn clean verify` | ✅ **本方案编制时已实测通过**（见 §1.1）：24 个数据层用例全绿、BUILD SUCCESS、Flyway 版本 2。**S0 可视为已完成**，开工前只需重跑一次确认环境未变 |
| **S1** | **工程改造**：pom 加 web+validation；`application.yml` 删 `web-application-type: none`、加 multipart/图片/会话/队列配置；新增 `AppProperties`、`JacksonConfig` | ✅ **已完成**（见「S1 完成记录」）：`mvn clean verify` 全绿（30 用例）、应用以 web 模式启动并占用 8080、`AppProperties` 绑定经实测断言 |
| **S2** | **公共件**：`ErrorCode`、`BusinessException`、`ApiResponse`、`GlobalExceptionHandler`、`EntityFactory`、`OperationLogService`、`SessionStore`、`SellerAuthInterceptor`、`WebMvcConfig` | ✅ **已完成**（见「S2 完成记录」）：`mvn clean verify` 全绿（**57** 用例）、无 token 请求 `/api/seller/**` → **HTTP 401 + `10002`**（MockMvc 与真实端口双验证） |
| **S3** | **`SellerAuthService` + `SellerSessionController` + `SellerAccountController`**（`I11-01`~`I11-03`） | ✅ **已完成**（见「S3 完成记录」）：`mvn clean verify` 全绿（**91** 用例）；真实端口 12 项实测通过——登录拿到 token（43 字符、`expire_at` 带 `Z` 且恰好 +30 分钟）、带 token 能访问、**改密后旧 token（含其它会话）立即 401**；审计日志文件 appender 首次实跑验证 |
| **S4** | **`SellerGoodsService` + `SellerProductController` 的 `I11-04`、`I11-06`~`I11-09`**（含图片上传 `I11-05`）；同时**完整实现 `ArchiveService`**（`takeGoodsOffline` 的前置依赖；§3.3.6 已完整定型，写半成品反而更差，故 S7 的剩余工作改为归档专项测试深度与 S6 接入） | ✅ **已完成**（见「S4 完成记录」）：`mvn clean verify` 全绿（**252** 用例）；真实端口 12 项实测通过（含**静态图片 `/images/**` 逐字节可取**）；`20001`/`20005`/`20006`/`30005` 均有用例与实测拦截。**并修复了一处只有真实端口才能发现的缺陷**——超限上传的 `20009` 因 Tomcat `max-swallow-size` 默认 2MB 而根本送不到客户端（见 §8.8 D-1／§6），已补真实容器用例守护且验证过该用例会失败 |
| **S5** | **`PasscodeService` + `BuyerIntentionService`**（买家端全部业务，**无 Controller**） | ✅ **已完成**（见「S5 完成记录」）：`mvn clean verify` 全绿（**399** 用例）；六项完成标志**全部达成**（口令码、位次、改信息不动位次、撤销、冻结期拒绝、队列上限拒绝）；另核对过 **S5 未引入任何买家端 HTTP 路径**。**并修复了一处会使应用无法启动的缺陷**（`SubmitRateLimiter` 的多构造器缺 `@Autowired`，见 §8.10 D-1） |
| **S6** | **`SellerIntentionService` + `SellerIntentionController`**（`I11-10`~`I11-14`） | ✅ **已完成**（见「S6 完成记录」）：`mvn clean verify` 全绿（**435** 用例）；五项完成标志**全部达成**（名单的 `rank`/`queue_count`/无 `token`；进入交易非队首被拒；标记成功顺序+归档；标记失败作废/重排且**重排后口令码仍有效**；查看口令码终态被拒）；真实端口 **22 项**实测通过（逐项明细见 §8.11 的 C 表）。**并修复了一处真实端口才会暴露的缺陷**——Controller 方法参数校验失败会落到兜底分支变成 **500**（应为 400 + `50002`，见 §8.11 D-1） |
| **S7** | **`ArchiveService` 收口**（若 S4/S6 中已内联则在此抽取并加 `INV-05` 前置） | ✅ **已完成**（见「S7 完成记录」）：`mvn clean verify` 全绿（**445** 用例）；`INV-05`/`INV-06` 断言通过、历史表**逐列**核对（历史商品 12 列、历史意向 8 列，且列集「不多不少」）。**注**：`ArchiveService` 已在 **S4 完整实现**，S7 未新增任何生产行为，只补验证深度。**本阶段最有价值的两件事**：① **变异验证**（3 次定向变异：顺序写反 → 6/10 失败；`deleteAllInBatch` → 6/10 失败；`save` vs `saveAndFlush` → **10/10 通过、不可观测**），由此校正了代码里两处**过度声称**；② 发现 **`trades[]` 在同一秒内无顺序保证**（`trade_start` 秒精度），已写入 §3.3.4 供 S8 使用 |
| **S8** | **`SellerHistoryService` + `SellerHistoryController`**（`I11-15`、`I11-16`） | ✅ **已完成**（见「S8+S9 完成记录」）：`mvn clean verify` 全绿（**458** 用例）；三项完成标志**全部达成**——① 倒序分页（`trade_end` 倒序，排序由仓储方法名内建）；② 详情含 `trades[]` 与 `trade_count`（且 `trade_count == trades.length()`、「N 次失败逐条可见」）；③ `20011` + **HTTP 404**。真实端口 **12 项**实测通过；四层响应字段集用**键集相等**断言（能发现「多带一列」） |
| **S9** | **日志收口**：`logback-spring.xml` 审计 appender、UTC 时间戳、90 天轮转；补全 8 类操作日志 | ✅ **已完成**（与 S8 合写于 §8.13）：appender／UTC／90 天轮转在 **S2** 已配好，本轮**实测确认生效**（独立 `-DAUDIT_LOG_PATH` 下拿到 4 条 HTTP 操作记录、`operator=seller`、时间戳为 `12:51Z` 而本机 `20:51`）。**补全 8 类**：`MARK_TRADE_FAILURE` 此前是**没有调用方的死常量**（第 5 类的失败侧从未记录），已补上；8 类现在各有调用点（走查表见 §8.13）。⚠️ **按用户指示「日志要求不高、无需测试保证」，本阶段不新增日志测试**，证据为真实端口实测 + 全量日志统计 + 调用点走查 |
| **S10** | **测试补全**：§8.3 全部用例 + §8.4 性能实测 | ✅ **已完成**（见「S10 完成记录」）：`mvn clean verify` 全绿（**462** 用例）；**§8.3 必测清单逐条对账**（覆盖矩阵见 §8.14 的 C 表，只补了 2 处真缺口）；**§8.4 性能实测**首次执行——查询 P95 ≤ 150ms（预算 500ms）、典型写 P95 ≤ 59ms（预算 1s）**均达标且余量充足**。**⚠️ 但「归档满队列（1000 条）」的两条写实测约 1.9~2.8s**：成因已实测锁定（Hibernate 6.6 不批处理这批 DELETE，`Com_delete` = 行数 + 1，`order_updates` 无效）。**口径经业务方裁定（2026-10-10）：按「写请求整体的 P95」判定 ⇒ 达标**，归档的绝对耗时**不计入该指标**且经确认可接受，**不做**批量删除优化（修法与代价备查于 §8.14 D-1）。唯一生产改动：`application.yml` 新增 `hibernate.jdbc.batch_size: 50` |
| **S11** | **文档更新**：`README.md` 补业务层说明；新增《业务层与接口层交接说明》（沿用数据层交接说明的体例） | ✅ **已完成**：① 后端 `README.md` 补上业务层与接口层说明（范围、Web/会话基线、war 启动、运行期环境变量、代码结构、16 接口速览）；② 新增 **[《业务层与接口层 · 交接说明》](../交接说明.md)**（12 节：环境与构建、环境核对表、代码结构、接口层 6 条硬口径、Service 7 条口径、**三个秒精度排序键的坑**、**已知限制与开放项**、测试与验证、初始账号、部署要点、**下一轮买家端 JSP 的 5 件必做**、交付物清单）。⚠️ **按用户指示，S11 不写实现记录** |
