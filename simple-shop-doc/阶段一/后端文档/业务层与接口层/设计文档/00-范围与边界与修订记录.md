# 0. 本轮范围与边界（先对齐，再动手）

### 0.1 本轮做

| # | 交付物 | 覆盖 |
| --- | --- | --- |
| 1 | **Service 层** | 卖家端全部业务（`FR-01` ~ `FR-11`、`FR-23`、`FR-24`）+ 买家端全部业务（`FR-12` ~ `FR-22`）的业务逻辑与事务编排 |
| 2 | **卖家端 Controller 层** | `I11-01` ~ `I11-16` 共 **16** 个 REST 接口（前后端分离，JSON + `Authorization: Bearer <token>`） |
| 3 | **DTO / 校验 / 异常 / 统一响应** | 请求 DTO、响应 DTO、字段校验器、业务异常与错误码、`@RestControllerAdvice` 全局异常处理 |
| 4 | **会话（session + token）** | 登录、退出、30 分钟无操作超时、改密后全会话失效 |
| 5 | **口令码生成与三态查询** | 12 位 `[A-Z0-9]` 生成、唯一性、归一化、三态判定 |
| 6 | **归档事务与交易流水** | 「标记成功」「手动下架」两条归档路径 + 流水追加 |
| 7 | **图片上传（服务端部分）** | 存储到服务器文件系统、库内只存路径、JPG/PNG + ≤5MB 双重校验 |
| 8 | **操作日志** | `NFR-12` 的 8 类关键操作，应用日志实现、保留 3 个月 |
| 9 | **测试** | Service 层集成测试（含并发、不变量、状态机合法性）+ Controller 层接口测试 + 既有 24 个数据层用例保持全绿 |

### 0.2 本轮**不**做

| 项 | 说明 |
| --- | --- |
| **买家端 JSP 页面** | `P10-01` ~ `P10-04` 的 JSP、原生 CSS、响应式布局**全部不做**；**不引入任何 JSP 依赖**（`tomcat-embed-jasper`、`jstl` 等一律不加）。买家端业务**只提供 Service 方法**，留待下一轮由 JSP Controller 直接调用 |
| **买家端 Controller** | `B11-01` ~ `B11-07` 的端点**不实现**（属 JSP 层，下一轮） |
| **卖家端 Vue 前端** | 只交付接口契约的实现，不写前端 |
| **部署与运维** | 容器化、备份策略（`OPEN-01`/`OPEN-02`）、数据导出（`OPEN-03`）仍为开放项 |
| **数据库结构变更** | **不动** `V1`/`V2` 迁移脚本，**不新增** `V3`。本轮是纯应用层开发 |
| **买家账号体系 / 通知机制** | `O-01`、`DEC-08` 已明确不做 |

### 0.3 买家端 Service 的必要性（为什么本轮必须写）

虽不做 JSP，但买家端业务是**卖家端业务的对偶**，且多处与卖家端共享同一套状态机与不变量。若本轮不写，下一轮做 JSP 时必然回头改动 Service 层，代价更大。本轮必须先落地：

| 买家端业务 | 对应 Service 方法 | 为什么现在写 |
| --- | --- | --- |
| `FR-12` 浏览当前商品 | `queryCurrentGoods()` 复用 | 卖家端 `I11-04` 与之读取同一份数据 |
| `FR-13` 提交意向 | `submitIntention()` | 涉及**序号表行锁**、口令码生成、队列上限 1000——是 `NFR-01`/`NFR-07` 的落点 |
| `FR-15` 三态查询 | `queryByToken()` | 与卖家端 `I11-14` 共享口令码有效性的**唯一判定式** |
| `FR-16` 改姓名电话 | `updateIntentionContact()` | 要保证「不影响位次」（`create_at` 与 `queue_order` 均不动） |
| `FR-17` 撤销意向 | `revokeIntention()` | 要保证「仅 `queued` 可撤销」 |
| `FR-18` 冻结期拒绝 | 内建于 `submitIntention()` | `INV-03` 必须在事务内校验 |
| `FR-19`/`FR-20`/`FR-21`/`FR-22` | 规则性约束，落在上述方法内 | 无独立入口 |
