# 需求澄清记录

针对升级需求A，对用户进行提问，得到了以下需求澄清记录

**问题1**
- 问：同时在售商品上限是多少？交易中的商品算不算？允许多个商品同时处于交易中吗？已有商品在售时还能发布新商品吗？
- 答：在售商品我没设上限，可以同时挂好几个。交易中（已冻结）的商品就不算"在售"了，算"交易中"；多个商品可以各自同时处在交易中，互不影响。已经有商品在售，照样能再发新的。

**问题2**
- 问：商品必须挂到二级，还是可以只挂一级？类别改名或停用后，历史商品怎么显示？选一级类别时是否包含其下所有二级商品？
- 答：商品必须挂到二级类别，不能只挂一级——一级只是分组，商品实际挂到它下面的某个二级上。类别我只有新增、重命名、删除，没有"停用"这一说；有商品的类别不能直接删，得先把商品挪走或挂到别的类别。改名后历史商品怎么显示、选一级时会不会顺带把下面所有二级商品一起筛出来，这两个我还没细想。

**问题3**
- 问：有账号后，同一买家对同一商品重复提交意向，是按账号识别还是按手机号识别？基线明确「不做去重、每次提交是独立记录」，升级后是否改变此规则？
基线「意向终态三类：成功 / 撤销 / 失败」，在买家侧订单历史中如何呈现？是否需要更细的状态文案（如「排队中」「交易中」）？
基线「卖家后台不显示口令码、也不显示任何与口令码挂钩的标识」——升级后是否仍成立？
基线「买家凭口令码修改姓名电话，不影响排队位次、不重新排队」——注册后改为账号登录，此规则是否保留？
- 答：重复提交怎么识别：按账号（用户名）识别，不按手机号——手机号本来就不唯一（前面说过一个手机号能注册多个账号）。去重规则没变：需求里仍然没有去重，同一账号对同一商品重复提交，就是多条独立意向记录，按提交时间排队、先到先得。
终态呈现：升级后意向终态实际只剩成功 / 失败两类。基线里的「撤销」是买家凭口令码做的操作，口令码一废弃，买家就没有撤销入口了，所以下单历史里「交易结果」字段就成功/失败两种。「排队中 / 交易中」这种更细状态文案，需求里没要求——历史记录只到「交易结果」这一层，不展示过程状态。
不显示口令码/挂钩标识：成立，而且比基线更彻底——口令码整个机制都废弃了，压根不存在口令码，卖家看的是账号（用户名），自然没有任何口令码或挂钩标识可显示。
「改姓名电话不影响排队位次」：这条不保留。「修改意向信息」是口令码时代的操作（凭口令码改），注册后意向信息直接取自账号（用户名、电话），买家既没有「修改意向信息」的入口（前面也确认了买家改不了资料），所以这条规则随口令码一起废弃了。

**问题4**
- 问：买家可修改哪些个人资料？改了手机号后，其历史交易记录归属如何判定？
- 答：这个版本没有给买家提供「修改个人资料」的入口——注册时填的用户名、电话、默认交易地点，注册后都没有买家端的修改功能。（能改密码的是卖家，买家这边没对应能力。）
所以「改了手机号后历史记录归属怎么判」这个前提本身不成立——买家改不了手机号。而且退一步讲，历史下单记录是挂在**账号（用户名）**名下的，不是挂在手机号名下：手机号只是联系方式，记录归属跟它不挂钩，改不改联系方式都不影响历史记录属于谁。

**问题5**
- 问：注册是否需要手机验证码？
- 答：不需要。注册就填用户名、密码、电话、默认交易地点这几项，没有手机验证码、也没有短信验证机制——电话只作为必填字段用于交易联系，不做真实性验证。系统本身不接短信能力，所以这块没有。

**问题6**
- 问：下单记录的定义是什么？提交意向就算下单，还是进入交易才算，还是仅交易成功才算？失败、撤销的算不算？
买家侧历史展示哪些字段？商品名、价格、提交时间、当前状态、交易结果？是否展示卖家信息？
历史列表的排序规则、时间范围、分页条数？
注册前（匿名时期）的购买记录能否迁移到账号下？凭手机号自动匹配吗？匹配不上怎么办？
商品已下架后，买家还能看到自己的历史记录吗？能看到商品当时的价格与图片吗？
买家查看自己历史时，能否看到自己当时的排队位次、以及同队列其他买家的信息？（涉及买家间隐私）
买家能否删除自己的历史记录？基线「历史只读」原则是否同样适用于买家侧？
- 答：「下单记录」定义：提交购买意向就算「下单」，那一刻生成记录（下单时间＝提交时间），之后交易结果再更新成成功/失败。所以成功、失败都在历史里；「撤销」这版没有这个概念——买家没有主动撤销意向的动作。
买家历史字段：至少商品名称、下单时间、交易结果（成功/失败）、交易时间。价格、当前状态都不在最小字段里；卖家信息也没有——单卖家模式，没必要展示卖家。
排序/范围/分页：按时间倒序，支持翻页。时间范围、每页条数都没定。
匿名时期记录迁移：没有迁移机制。不凭手机号自动匹配，也没有「匹配不上怎么办」的处理——注册前的匿名记录不带过来。
商品下架后：自己的历史记录照常能看，跟商品下不下架无关。但记录里只有商品名、下单时间、交易结果、交易时间，不含价格和图片，所以看不到「当时的价格和图片」。
排队位次 / 同队列其他买家：看不到。买家历史只显示自己的记录，没有排队位次，也看不到同队列其他买家的任何信息。
能否删除历史：不能。历史只读，买家侧同样只读，跟基线原则一致。

**问题7**
- 问：商家可见的客户字段范围是哪些？用户名、姓名、电话、默认交易地点全部可见？是否需要对电话做脱敏处理？
客户信息是「注册即可见」还是「产生交易后才可见」？（这是最关键的一条隐私边界，两种方案数据权限完全不同）
未注册（游客）买家的记录商家可见吗？以姓名+电话的形式展示，还是另作处理？
购买历史的展示维度：按客户维度查看（点客户→看他的所有购买），还是按商品维度，还是两者都要？
商家能否导出客户信息或购买历史？（若可以，合规风险显著放大，建议明确禁止或限制）
客户列表是否需要搜索/筛选？按手机号、姓名、注册时间还是按消费次数？
商家是否需要看到客户的注册时间、累计交易次数、累计成交金额等统计类字段？
合规确认：商家查看客户联系方式与购买历史，是否已确认符合《个人信息保护法》要求？是否需要用户注册时的授权条款与隐私政策？
答：先说个总前提：注册字段是用户名（不是姓名），所以商家看到的客户身份是用户名，不是真实姓名。逐条答：
可见字段：用户名、电话、默认交易地点、注册时间。没有「姓名」这项——注册时就没设姓名字段。电话不脱敏，完整给商家看，因为它是交易联系方式；约束只在「不得向第三方泄露」。
注册即可见：卖家看的是「所有注册客户」列表，不是「产生交易后才可见」。注册了就在客户列表里。
未注册游客：不可见。游客不能提交意向、不产生记录，也不进客户列表，所以没有「姓名+电话展示」这回事。
购买历史维度：两个维度都要——按客户看他的购买历史（第11章），按商品看该商品的意向购买人列表（第12章）。
导出：不能。只有后台查看，没有导出功能。
搜索/筛选：没有。就是列表查看。
统计字段：注册时间可见；累计交易次数、累计成交金额这类统计字段没有。
合规：需求里只有隐私保护约束——商家查看的客户信息「仅限交易所需字段」「不得向第三方泄露」「仅用于交易撮合与售后联系」。没有明确的《个保法》合规条款、注册授权条款、隐私政策这些要求。

**问题8**
- 问：描述支持哪些富媒体？（图片外链？视频？）脚本/XSS 白名单如何界定？
- 答：富媒体这块：描述支持富文本，可以内嵌图片和视频，就这两类。至于图片是不是「外链」、还是上传的，这个需求里没写那么细。脚本 / XSS 白名单怎么界定——这个超出需求讨论范围了，我只负责聊产品需求。

**问题9**
- 问：口令码、排队、冻结、递补"到底废不废？
- 答：口令码：不用了。买家现在能注册登录，登录之后自己就能查意向、管意向，还要额外的口令码干嘛？注册账号已经把口令码那套替代掉了。
排队：保留。多商品也一样，每个商品独立排队，先到先得。
冻结：保留。交易中的商品照样冻结，冻结期间不接受新意向。
递补：这个跟原来不一样了。原来交易失败后，排队里的意向会自动依序递补上来；现在交易失败就是商品恢复在售，那一单是作废还是重新排队，由我在后台确认，不是自动递补了。
简单说：口令码废了，排队和冻结留着，递补变成「卖家确认」而不是「自动递补」。

**问题10**
- 问：图片张数上限是多少？多张图片里是否有「主图」概念（列表页与详情页首图用哪张）
- 答：至多 9 张。有主图概念——列表和搜索里只显示主图，详情页看全部图片（JPG/PNG，单张 ≤5MB）；主图具体取哪张（第一张还是我指定）没写死。

**问题11**
- 问：多个商品同时在售时，买家端怎么展示？是改为商品列表页 + 详情页两级，还是仍按单品展示？
- 答：改成列表页 + 详情页两级。列表里能看到每件在售商品的名称、价格、主图、所属类别，点进去看完整详情

**问题12**
- 问：是否仍保留「发布后商品信息即定死、不可修改」的行为？
- 答：我没有「修改商品信息」的操作——商品发布后，名称、描述、图片、价格、类别这些没有改的入口；只有库存可以手动调。

**问题13**
- 问：库存什么时候扣减：买家提交购买意向时扣，还是交易成功标记后扣？交易失败是否回滚？库存降到 0 触发自动下架时，正在排队的购买意向怎么处理？库存数量是否限制排队人数上限？例如库存 3 时，允许超过 3 个买家排队吗？
- 答：交易成功标记后才扣库存；提交意向不扣。交易失败本来就没扣，所以不存在回滚。正在排队的购买意向怎么处理，
这个我还没细想。库存不限制排队人数。库存 3 也允许超过 3 个人排队，第 4 个买家照常排队、照常能看到商品；只有库存归零、商品下架后才停止收新意向。

**问题14**
- 问：1.删除一个已经挂着商品的类别时怎么办？2.发布时库存允许填 0 吗？如果允许，商品发布后立即处于下架状态，卖家自己都看不到；如果不允许，是否应改为要求库存 ≥1？3.库存售罄时排队的买家怎么处置4.补库存重新上架后，原队列是否恢复？买家如何得知补货？5.删除类别时，挂在该类别下的商品怎么办？卖家能不能把已发布的商品换到另一个类别？
- 答：挂着商品的类别不能直接删，得先把商品处理掉——移除，或者改挂到其他类别。
我写的是「非负整数」，0 也算在内；但你这一问提醒我了——填 0 直接下架、卖家自己都看不见，确实别扭。那就按你说的，发布时要求库存 ≥1。
这个我还是没定死。按常理，商品售罄下架了，排着队的意向就该作废；但你要说保留着等补货，也行。这块你提个方案。
补货重新上架后重新收意向，原队列我不倾向恢复；系统里没有主动通知买家这一说，买家是自己刷新看到商品重新上架才知道补货了。
和第 1 条一样——删类别前先把商品移除或改挂到其他类别，有商品的类别不能直接删。商品能改挂到别的类别，所以换类别是可行的；平时主动给商品换类别这个操作需求里没单独列，你就按「能改挂」处理。

**问题15**
- 问：1、注册是“允许但不强制”还是必须登录、登录后还要不要口令码？
2、注册字段范围、密码加密、找密码与改资料要不要做？
3、历史下单要看到什么程度？
4、排队位次与客户自行取消意向要不要做？
5、商家能看客户哪些字段、是否脱敏、“购买历史”含不含未成交？
6、存量匿名订单如何归属、同一客户重复提交是否限制？
- 答：1、注册是否强制：浏览商品不用登录；但要下单（提交购买意向）就必须先注册并登录。登录后身份就是账号了，口令码自然用不上。
2、注册字段与密码：注册字段就四个——用户名、密码、电话、默认交易地点（电话必填，交易地点选填）。密码要加密存、不能明文，强度要求跟卖家账号一样。至于找回密码、改资料这些，我暂时没这个要求，不做。
3、历史下单看到什么程度：每条至少能看到商品名、下单时间、交易结果（成功/失败）、交易时间，按时间倒序排，能翻页就行。
4、排队与取消：排队按先到先得，各商品的队列各排各的。至于给买家展示"你排第几"、客户自己取消意向——我都没要求；取消/重排目前是我（卖家）在后台确认的。
5、商家看客户：我能看到用户名、电话、默认交易地点、注册时间。脱敏没做过，电话本来就是拿来联系的。"购买历史"就是他的下单记录带交易结果，成功的、失败的都在里面。
6、存量匿名订单与重复提交：以前用口令码认领的那些旧单子，注册之后怎么并进账号，我还没细想，你提醒到点子上了。同一客户对同一件商品反复提交意向要不要限制，我也没规定过——你觉得呢？

**问题16**
- 问：买家除了能提交意向、查看历史之外，能不能查看自己非终态的意向及其进展？注册时默认交易地点是选填，那么是否允许注册后补填这个字段？
- 答：买家这边的能力就是「提交购买意向」和「登录后看历史下单记录」两项，没有「查看进行中意向进展」这一项——意向提交后交易怎么推进，是卖家后台那边跟进的事，买家不用单独盯进度。
默认交易地点是注册时选填的：想填就填，不填也不影响。注册之后我没有做「改资料/补填」的功能，填了的字段就固定了。

**问题17**
- 问：商品有库存时，是否允许手动下架?设置库存为0这个操作，是否就是一种“手动下架”的方式?
- 答：商品有库存时也可以手动下架——手动下架是我主动把商品撤下来，跟库存多少没关系。
但「设置库存为 0」不是手动下架，它走的是另一条路：库存减到 0 会自动触发下架。这俩是两种不同的下架情形——一个是卖家主动下架，一个是库存规则自动下架。

**问题18**
- 问：这个版本还有手动冻结这个操作吗?既然删除分类需要移除商品的引用，那么商品是否能够修改类别，其他字段能否修改?商品能否直接删除，若能，历史记录怎么处理?
- 答：手动冻结没有了——这个版本冻结是自动的：我跟某个买家进入交易流程时，商品自动冻结，不用再手动去冻/解。
类别可以改挂：删除类别时，该类别下的商品要「移除」或「改挂其他类别」。库存也能手动调整。但名称、价格、描述、图片这些字段，发布之后没有「编辑」功能，就是固定的。
商品不能直接删除，只能「下架」（交易成功下架、库存归零自动下架、手动下架这几种）。下架之后商品进历史记录，我在后台的历史商品里还能看到。

**问题19**
- 问：买家从哪个合法入口打开冻结商品详情（历史记录、直链、卖家分享链接、其他）？「已下架」（含库存为0自动下架）商品详情是否允许打开？若允许，能否提交意向？
- 答：冻结商品不在列表和搜索里，唯一合法入口是直链（商品详情 URL、分享链接等）。打开后只能看，不能买、不能提交意向。已下架（含库存 0 自动下架）商品，买家端打不开详情、不能提交意向，它已经从买家端彻底退出了。

**问题20**
- 问：1、成交后库存还有剩余，商品是否自动回到在售？
2、买家能否自行撤销已提交的下单记录？
3、重新上架的库存由卖家填写，还是单独做「补货」动作？
- 答：1、成交（交易成功）后商品就下架了，哪怕库存还有剩余也不会自动回到在售，得我在后台手动重新上架。交易失败才会自动恢复在售。
2、买家不能自己撤销已提交的下单记录。意向作废还是重新排队，是卖家在把这次交易标成「失败」时由我确认的，买家端没有撤销入口。
3、补货就是我在后台直接改库存数字，改完再重新上架，没有单独的「补货」动作，也没有别的库存填写入口。

**问题21**
- 问：未登录能不能浏览、能不能下单？
- 答：浏览商品不用登录；但提交购买意向（下单）前必须注册登录。

**问题22**
- 问：卖家「手动下架」时，队列里的意向怎么办？手动把在售商品库存调到0，是否也禁止（改为必须先下架再调）？
- 答：「手动下架」在下架状态里是有这一种的（和交易成功下架、库存 0 自动下架并列），但需求里没写手动下架时排队意向具体怎么处理。
能确定的是：手动下架后商品退出在售，不展示了、也不能再买、不再收新意向。队列里那些排着的人自然就买不到了。但到底是「直接作废」还是「保留着、等我重新上架后再接着排队」，这个细节我还没定。
在售商品可以直接把库存手动调到 0，不需要先下架再调。
调到 0 的那一刻，就触发了「库存为 0 自动下架」——商品自动退出在售，不再展示、不再收新意向。等你想重新卖，补货把库存调回正数，再重新上架就行。
也就是说，手动调库存和自动下架是连着的：你调到 0，它就自动下架，不用先走一步「手动下架」。

**问题23**
- 问：1、卖家查看历史意向的入口在哪里，是通过商品详情查看，还是单独的历史页允许筛选与搜索？历史意向是否需包含“重新排队”的流水记录，还是只记录结果？2、库存为0自动下架后允许修改库存重新上架，那么在售商品是否允许修改库存？除了这两个修改库存渠道外，还有没有其他修改库存的渠道（例如手动下架/交易成功下架后的重新上架是否能修改库存）？
- 答：入口走「历史商品」：卖家后台看历史商品列表，点开某个商品，看它的「意向购买人」列表（用户名、电话、提交时间、交易结果）。没有单独的「历史意向」页，也不要求筛选/搜索。意向记录只记结果、不记「重新排队」的流水——重新排队是交易失败时卖家做的处理，最终落库的只是交易结果。
改库存就一个渠道：卖家在后台手动调整库存。在售商品可以改，库存归零下架后补货也能改、改完重新上架。手动下架、交易成功下架没有单独的改库存渠道——交易成功下架的商品是终态（进历史商品），不会再上架。

**问题24**
- 问：交易成功下架的商品如果仍有库存，是否可以从终态恢复上架？
- 答：不能。交易成功下架是终态，商品进历史（已售商品），不管还剩多少库存都不会再恢复上架。重新上架只有一种情况——库存卖到 0 自动下架，我补货之后再重新挂出来。

**问题25**
- 问：若有一个商品库存为2，那么出现一次交易成功后，它是直接下架还是库存变为1重新上架
- 答：库存 2 的话，成交 1 件，库存就减到 1，商品继续在售，不用重新上架——我一件一件卖，卖到库存 0 才自动下架。
「交易成功下架」说的就是卖完最后一件（库存归零）时的下架，不会出现「还剩库存却已经下架」的情况。所以上一条那个「交易成功下架后仍有库存」的前提本身不成立。

**问题26**
- 问：那么是否可以这么理解：在售阶段手动修改库存为0，商品下架但不进入终态，可以修改库存重新上架；但是交易导致的库存为0，商品就直接进入终态进历史商品了，不能修改库存重新上架。
- 答：对，就是这个理解。我手动把库存改成 0，走的是「库存归零自动下架」——商品不是卖完了，只是暂时下架，补货之后能重新上架；但要是成交把库存卖到 0（卖出最后一件），就是「交易成功下架」，商品卖完了，进历史商品，不会再挂出来。  

**问题27**
- 问：由于买家有账号，提交意向时，是否只需要填收货地点？
- 答：提交意向不用再填任何字段，也不用填收货地点——电话（必填）、默认交易地点（选填）都在注册时填好了，提交意向就是登录后点「我要购买」，直接用账号信息。
另外系统里没有「收货地点」这个说法：这是线下交易，一手交钱一手交货，没有收货环节。注册时那个选填字段叫「默认交易地点」，是用来定线下碰头地点的。
