# 后端数据库脚本目录

> 本目录存放各阶段的建表脚本、历史归档与当前设计草稿，**不参与运行期加载**；Flyway 只执行 src/main/resources/db/migration 下的版本脚本。
> 目录说明统一写在本文件与阶段目录的「目录.md」，本目录内不再放 README.md。

## 布局

| 目录 | 内容 | 说明 |
| --- | --- | --- |
| 阶段一/ | V1、V2 基线，两个整库备份 | 单商品、口令码时代；仅作历史参考 |
| 阶段二/ | 00～03 设计草案、refactor/ 重建脚本 | 草案已合并为阶段二 V1，保留作对照；refactor 只适用于阶段二 12 表基线 |
| 阶段三/ | 交付后归档 | 定稿的 V3 与最终基线，交付时放入 |
| 草稿/ | 阶段三设计草稿 | 删除、修改、新增三个脚本，定稿后并入 V3 |

## 使用约定

- 已发布的 Flyway 脚本不得修改；阶段三的变更从 V3 开始，V1/V2 保持原样。
- 草稿按 01 删除 → 02 修改 → 03 新增 的顺序执行，且应合并为同一个 V3；01 会删表，执行前先整库备份。
- 草稿假定目标库已执行到阶段二 V1/V2（12 张表）；阶段一结构的库不能直接跑。
- MySQL 的 DDL 不能回滚：V3 中途失败会留下半迁移状态，开发库按重建处理（备份 → 删库 → 重跑 V1/V2/V3）。
- 阶段二的 refactor/dev_reset.sql 会删除 simple_shop 与 simple_shop_test，只能在开发环境使用；它只做删库重建，阶段三可直接复用，不再另写脚本。
- 文件命名：正式迁移用 V{序号}__说明.sql，阶段归档沿用原文件名，草稿用两位序号前缀。
- 阶段一的 backup.sql、test_db_backup.sql 是整库导出，含口令哈希与业务数据，不要提交新的备份文件。
