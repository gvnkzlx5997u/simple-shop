### 为什么 §8 被拆到两个部分

§8「测试策略」在原文里是一整章，但它混了两类内容，拆分时按**性质**分开：

| 小节 | 性质 | 归属 |
| --- | --- | --- |
| §8.1 与既有测试的关系、§8.2 测试分层、§8.3 必测用例清单、§8.4 性能验证 | **前瞻**：规定「要测什么、怎么分层」 | 设计文档 |
| §8.9 用例表（CSV）测试约定 | **前瞻**：后续步骤要沿用的写法约定 | 设计文档 |
| §8.5 S1 ~ §8.8 S4 完成记录 | **回顾**：逐阶段的交付物、证据、发现 | 实现过程记录 |
| **§8.10 S5 完成记录** ~ **§8.14 S10 完成记录**（拆分后新增；**S11 不单独成篇**） | **回顾** | 实现过程记录 |

> **⚠️ §8.10 ~ §8.14 都是拆分之后新增的**（v11 落档 S5、v12 落档 S6、v13 落档 S7、v14 落档 S8+S9、v15 落档 S10）。
> 原文的 §8 只到 §8.9；后续每完成一个阶段，**在 `实现过程记录/` 新增一篇、编号沿用 §8.x 往下递增**——
> 这样既有文档的 § 编号不会被扰动（代码里的百来处引用依赖它）。
> ⚠️ **§8.13 是一篇合写**（S8 与 S9 同一轮交付）；**S11 不写实现记录**（用户指示）——它的产物是 [交接说明.md](交接说明.md)。

因此 `设计文档/08-测试策略与用例表约定.md` 的内容在原文中是**不连续**的两段（第 1432–1546 行与第 1866–1903 行），
文件头的注释里已注明。
