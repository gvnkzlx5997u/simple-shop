### 11.1 由本次答复**新增/变更**的口径（实现时特别注意）

| # | 变更 | 说明 |
| --- | --- | --- |
| 1 | **`markTrade*` 收紧为要求 `freezeBy == trade`** | 原稿只校验 `status == frozen`。按 Q-1 的答复收紧。**该分支实际不可达**（`trading` 意向只可能来自 `enterTrade`），作为**防御性断言**保留；触发时按 `20004` 拒绝（**不擅自新增错误码**，见 §4.3 的归属规则） |
| 2 | **DTO 的时间字段一律用 `String`** | 由 Q-11 直接推出：既然服务端不做展示层转换，就在 DTO 里**显式**用 `ZoneOffset.UTC` 格式化，**不再**保留 `LocalDateTime` + 自定义 Serializer 的方案（避免全局配置漂移） |
| 3 | **`disposal` 不用枚举** | Q-14；`30006` 由 Service 显式抛，**不依赖 Jackson 异常解析** |
| 4 | **`createAt` 由 Service 显式写** | 全项目统一口径（§3.4 末），不依赖 `@PrePersist` |
| 5 | **容器化的 5 条落地要求** | 图片挂持久卷、容器时区 UTC、构建须在工程根目录、数据库容器就绪顺序、**不用 `HttpSession`**（§5.3） |
| 6 | **「查看口令码」记日志但不记码值** | Q-4/Q-9 双重确认；`OperationLogService` 只记「谁在何时看了哪条意向」（§3.3.8、`12-H`） |
| 7 | **DTO 注解只判「有没有」，不判「对不对」**（**v8 新增**） | **实现 S3 时发现原稿会产出错误结果**：`@Size` 注解会在进 Controller 前把请求拦成 `50002`+HTTP 400，使契约指定的业务码（`10004`/`20007`/`20008`/`30007`，均为 HTTP **200**）**永不可达**。**判据**：先查 §4.3 里该字段有没有专属码——有则 DTO 只留 `@NotBlank`，无则可写长度/区间。**逐字段表见 §4.6.3**；`10004`/`20007`/`20008`/`20010` 已随 S3/S4 落地并各有用例（§8.7 D-1、§8.8 D-1），`30007`/`30006` 已随 **S6** 落地（§8.11 的 C 表与 `intention-failure-cases.csv`） | 
| 8 | **媒体类型协商失败 → `400` + `50002`**（**v8 新增**；**v12 同类扩充见第 12 条**） | §11.3.4 的 6 个状态码是**枚举式**的，未含 415/406。实现时发现不处理会落到兜底分支变成 **500**+`50000`，把「客户端写错 `Content-Type`」误报成「服务端内部错误」。归入 400（§11.3.4 对 400 的定义本就含「参数格式错误」）。**未新增错误码**。另：**405（方法不支持）按契约未规定处理，保留 REST 惯例**——它与媒体类型错误不同类（路由 vs 报文），理由见 §4.2 |
| 9 | **报文解析失败的日志不得回显请求体**（**v8 新增**） | Jackson 的解析异常消息**从请求体原文生成**，实测 `{"password":Abcd@1234}` 会得到 `Unrecognized token 'Abcd': ...` ⇒ **客户端把报文写坏就会把口令明文写进留存 3 个月的日志**（违反 `12-H`）。已改为只记**异常类别 + 行列号 + 未知字段名**（字段名是元数据，不是用户数据） |
| 10 | **`UtcIso8601` 无条件截断到秒**（**v8 新增**） | **必需而非洁癖**：库列是 `datetime`（无小数秒），而 `DatabaseTimeProvider.utcNow()` 带纳秒；同一 DTO 字段两种来源都会走到，「刚 persist 未重读」那条路径不截断就会输出 `...T12:34:56.123456Z`，违反 §8.3 断言 #3 |
| 11 | **`I11-10` 的终态行也带位次**（**v12 新增**） | 按第 11 章 §11.5 的**字面口径**实现：只有 `trading` 的 `rank` 为 `null`。⚠️ 但 §9.5.3 的位次定义只覆盖 `queued`——终态意向已退出队列。**已登记为口径观察项 O-1**（§8.11），若上游确认终态行应为 `null`，改 `rankOf()` 一行即可，接口形状不变 |
| 12 | **Controller 方法参数校验失败 → `400` + `50002`**（**v12 新增**） | **实现 S6 时发现**（真实端口实测）：`@RequestParam` 上的约束由 Spring 6.1 的**内建方法校验**执行并抛 `HandlerMethodValidationException`——它**自带 400 语义**，却因不在任何分支里而落到兜底 `@ExceptionHandler(Exception.class)`，被改写成 **500**+`50000`（实测 `?page=0`、`?page_size=101`、`?intention_id=`）。与第 8 条**同一类**（客户端写错请求被报成服务端错误）。**未新增错误码**；另修正为报**线上参数名**（`page_size`）而非 Java 形参名。见 §4.2、§8.11 D-1 |
