# 2. 工程与配置改造

### 2.1 `pom.xml` 依赖变更

**新增**（仅两个，且都属本轮必需）：

```xml
<!-- 卖家端 REST 接口层（I11-01 ~ I11-16） -->
<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-web</artifactId>
</dependency>

<!-- 请求参数校验（@Valid / @NotBlank / @Pattern / @Size） -->
<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-validation</artifactId>
</dependency>
```

**明确不新增**（避免越界与惩罚性改动）：

| 依赖 | 为什么不加 |
| --- | --- |
| `tomcat-embed-jasper` / `jstl` / `spring-boot-starter-tomcat` 的 JSP 支持 | 买家端 JSP 不在本轮范围（用户明确「jsp 相关依赖无需引入」） |
| `spring-boot-starter-security` | 会话是**自定义 token**（`C-07`、`DEC-13`），不用 Spring Security 的过滤器链；引入会带来默认登录页与额外配置面。`spring-security-crypto` 已在，够用 |
| `spring-boot-starter-thymeleaf` / `freemarker` | 无服务端页面 |
| Swagger / springdoc-openapi | 契约已在第 11 章成文；加 swagger 会引入版本耦合，非必需。**建议用 `.http` 文件或 Postman 集合作接口冒烟**，见 §9.5 |
| 缓存 / 消息队列 | `C-04` 明确排除 |
| 二级缓存 | 同上 |
| Lombok | 数据层未用；本轮不引入，避免给评审带来「编译期魔法」的解释成本 |
| MapStruct / ModelMapper | DTO 映射量小（16 个接口），手写静态工厂更可控、更好审 |

> **保留**：`surefire` 的 `-javaagent:byte-buddy-agent` 配置（交接说明 §2 第 4 项，本机必需，对其它环境无副作用）。

**打包方式：war（✅ S2 已实施，计划外变更）**

```xml
<packaging>war</packaging>
<build>
  <finalName>simple-shop</finalName>   <!-- 产物 target/simple-shop.war -->
  ...
</build>
```

| 项 | 口径 |
| --- | --- |
| **为什么是 war** | **下一轮买家端为服务端渲染的 JSP**（`C-05`、`A-02`、`A-05`）。JSP 由 servlet 容器编译，需要 `WEB-INF` 下的 web 资源结构，**jar 无法承载**。本轮先改打包方式，下一轮只需加 `tomcat-embed-jasper` + `src/main/webapp/WEB-INF/views` |
| **主类** | 改为 `extends SpringBootServletInitializer` 并实现 `configure(...)` ⇒ 同时支持 `java -jar`（开发期）与放进外部 Tomcat `webapps/`（部署期） |
| **⚠️ embedded Tomcat 本轮【保留】** | **不**设为 `provided`。否则 `java -jar` 将因缺少 servlet 容器**无法启动**，开发与自测失去最方便的验证手段。JSP 直出所需的 `tomcat-embed-jasper` 属下一轮依赖，**本轮不加** |
| **何时收紧** | 若确定「只用外部容器、不再需要 `java -jar`」，再把 embedded Tomcat 与 `jakarta.servlet-api` 同时设为 `provided` |

> **⚠️ 与验证方式的关系**：S0/S1/S2 的启动验证**都走 `java -jar`**。这也正是本轮不能把 embedded Tomcat 设为 `provided` 的实际原因——不是理论取舍，而是会当场打断验证链路。

### 2.2 `application.yml` 调整

```yaml
spring:
  main:
    # ⚠️ 删除原来的 web-application-type: none（交接说明 §2.2 已预告：加 web 层时删掉此项）
    # 不写 = 默认 SERVLET
  servlet:
    multipart:
      max-file-size: 5MB        # C-14、NFR-11
      max-request-size: 6MB
  jpa:
    open-in-view: false          # 保持；Service 必须在事务内取完数据再返回 DTO

simple-shop:
  image:
    directory: ${IMAGE_DIR:./data/images}   # C-08、DEC-09：图片存文件系统
    url-prefix: /images                       # 对外访问前缀
  session:
    timeout-minutes: 30                       # DEC-13、NFR-04
  queue:
    max-size: 1000                            # DEC-23、NFR-07
  # 首次发布/上传的限流阈值（NFR-17：提交意向同一 IP ≤10 次/分钟）
  rate-limit:
    submit-intention-per-minute: 10
```

> **`open-in-view: false` 必须保持**：Service 返回 DTO、不返回实体；所有懒加载字段（`Intention.goods`）在事务内取完。

### 2.3 包结构（建议）

```
com.simpleshop
├── SimpleShopApplication.java              （已有，不改）
├── persistence/                            （已有，仅新增实体工厂）
│   └── entity/
│       ├── ...（7 个实体）
│       └── EntityFactory.java              【新增】绕开 protected 构造
├── security/                               （已有）
├── service/                                【新增】业务层
│   ├── SellerAuthService.java              FR-01、FR-02
│   ├── SellerGoodsService.java             FR-03 ~ FR-06、FR-23
│   ├── SellerIntentionService.java         FR-07 ~ FR-10、FR-24
│   ├── SellerHistoryService.java           FR-11
│   ├── BuyerIntentionService.java          FR-12 ~ FR-22（无 Controller）
│   ├── ArchiveService.java                 归档事务（被上两者调用）
│   ├── PasscodeService.java                口令码生成/归一化/三态判定
│   └── OperationLogService.java            NFR-12
├── service/dto/                            DTO（请求/响应/内部命令对象）
├── service/exception/                      BusinessException + ErrorCode
├── service/support/                        校验器、分页参数、UTC 格式化
├── session/                                【新增】会话
│   ├── SessionStore.java
│   └── Session.java
├── web/                                    【新增】卖家端接口层
│   ├── SellerSessionController.java        I11-01、I11-02
│   ├── SellerAccountController.java        I11-03
│   ├── SellerProductController.java        I11-04 ~ I11-09
│   ├── SellerIntentionController.java      I11-10 ~ I11-14
│   ├── SellerHistoryController.java        I11-15、I11-16
│   ├── SellerAuthInterceptor.java          token 校验（拦截 /api/seller/**）
│   ├── WebMvcConfig.java                   注册拦截器、静态图片映射
│   ├── ApiResponse.java                    统一响应
│   ├── GlobalExceptionHandler.java         @RestControllerAdvice
│   └── dto/                                仅 Web 层的入参出参（如与 service/dto 重合则复用）
└── config/
    ├── JacksonConfig.java                  UTC ISO 8601、BigDecimal 字符串
    └── AppProperties.java                  @ConfigurationProperties
```

> **分层取向：不做「Controller → Service → Repository」之外的抽象**。不引入 Interface + Impl 的双层写法——本项目只有一种实现，接口层是纯噪音。
