**S1 期间发现并记录的两件事**

1. **`application.yml` 的会话配置键改用 `Duration` 简写**（`timeout: 30m` / `timeout-tolerance: 60s` / `purge-interval: 60s`）。原先写成 `timeout-minutes: 30` 也**能**被 Spring 的 `Duration` 转换器识别，但简写形式语义更明确、也不依赖「单位后缀」这条隐式规则。
2. **`spring-boot:run` 传 JVM 参数时的 PowerShell 坑**（环境相关，非代码问题）：`mvn spring-boot:run "spring-boot.run.jvmArguments=-D..."` 在 PowerShell 下会被**按空格拆参**，报 `Unknown lifecycle phase`。规避方式：改用 `java -jar target/*.jar` 直接运行（本方案即如此验证），或对该参数加转义/用 `--%` 停止解析。

**`JacksonConfig` 的两项决策已落到测试**（避免只写在注释里）：

| 决策 | 测试用例 |
| --- | --- |
| **不关闭** `FAIL_ON_UNKNOWN_PROPERTIES`（契约未定义字段 → `50002`，不静默忽略） | `rejectsUnknownProperties` |
| **不得**配置 `default-property-inclusion` / `@JsonInclude(NON_NULL)`（`null` 键必须保留） | `keepsNullFields` |

> **与方案 §4.6 的一处联动**：`JacksonConfig` **刻意不注册** `LocalDateTime` / `BigDecimal` 的全局 Serializer。因为 DTO 的时间字段是 `String`（§4.6.4）、金额字段是 `String`（§4.6.4），转换点在 DTO 静态工厂。若在全局再加一层，就形成**双源**，两边不一致时极难排查。`doesNotWriteDatesAsTimestamps` 用例只保证「万一某处直接序列化了 `LocalDateTime`，不会退化成纪元数字」。
