# simple-shop 卖家前端

simple-shop 的**卖家后台**，前后端分离的 Vue 单页应用。

本工程**只包含卖家端**。买家端是后端服务端渲染的 JSP（位于 simple-shop-backend 工程的 src/main/webapp/WEB-INF/views），不在本仓库内；两端共用同一套后端接口。

---

## 二、快速开始

### 1. 启动后端

必须在**后端工程的根目录**执行（默认 8080 端口）：

    cd simple-shop-backend
    mvn spring-boot:run

### 2. 启动前端

    cd simple-shop-frontend
    npm install
    npm run dev

打开 http://localhost:5173 ，用初始账号登录：

    账号：seller
    口令：Abcd@1234

### 3. 开发代理与后端地址

开发服务器已把 **/api** 与 **/images** 代理到 http://localhost:8080（见 vite.config.ts），本地开发无需处理跨域。

部署（或后端不在本机）时，用环境变量 **VITE_API_BASE_URL** 指定接口前缀；不设置时默认 **/api**。

## 五、重要决定

### 1. 本期不做「查看口令码」（重点）

需求（FR-24、S10-04）把口令码定义为首页意向名单中的一列。但该项需求是**开发方加入的**、优先级较低、仅作为买家忘记口令码时的兜底手段，其合理性**尚未取得业务方同意**，因此：

- 前端**本期不做任何口令码入口**：首页名单不渲染该列，历史商品详情也不提供；卖家侧无法查看口令码原文。
- 后端接口（I11-14）**保留不动**；前端 src/api/intention.ts 中的 getPasscode 定义以**注释形式保留**，等下一期与业务方确认后再决定是否启用。
- 该决定不影响买家端：买家仍可用口令码自查意向。

### 2. 业务拒绝 = HTTP 200 + 业务码

后端把「队列非空」「非队首」这类业务规则拒绝视为**正常分支**，返回 HTTP 200 + 业务码；只有 10002→401、50002→400、20011→404、50000→500 四个例外。

前端 request() 对这两种情形一律抛 ApiError（含 code / httpStatus），页面按 code 分支处理。

**message 不用于展示**：它是给日志与排查用的 ASCII 英文；界面文案统一由 constants/messages.ts 的 apiCodeMessage(code) 映射（即第 10 章的 M10 文案表）。

### 3. 「进入交易」按位次判定，而不是列表第一行

意向名单包含终态意向、按 queue_order 升序返回，因此**字面第一行可能是已失败 / 已撤销的行**。真正的队首是 status 为 queued 且 rank 为 1 的那一行；后端也只接受队首（否则返回 30002）。因此按钮可用条件按**位次**判断。

### 4. 交易中的意向不单独做卡片

后端分页返回**全部意向**，trading 行也在列表里，且**不保证落在第 1 页**。若前端把它过滤出来单独放卡片，会出现「卡片可能拿不到 intention_id」和「该页行数与 total 不一致」两个问题。

因此决定：trading 行**留在列表里**，「标记成功 / 标记失败」按钮就放在该行；列表与分页口径与后端完全一致。

### 5. 发布商品的两个接口：图片在提交时才上传

后端的上传（I11-05）与发布（I11-06）是两个接口。前端流程：

1. 选图时**只做本地校验与预览**（JPG / PNG、不超过 5MB），不落盘；
2. 点「发布」→ 校验 → 二次确认；
3. 确认后**先上传拿到 pic_url，再带着它发布**；没有选图则只调发布一次。

好处是「选了图又取消」不会提前落盘。代价是若上传成功但发布失败，会留下一个孤立图片文件（本系统无清理需求，属已接受）。

### 6. 无图占位图两端共用

素材为 src/assets/product.svg。卖家端由组件直接导入使用；买家端把同一份文件放在 simple-shop-backend/src/main/resources/static/buyer/product.svg，在 index.jsp 中以 /buyer/product.svg 引用。两端的占位样式都用 object-fit: contain，避免图标被裁切。

### 7. 原生 CSS，不引入 UI 库

按技术选型要求，全部用原生 CSS：全局基础样式（按钮、输入、表格、卡片、弹窗、标签等）在 assets/base.css，组件内用 scoped 样式。Toast、确认弹窗、分页等均为自行实现。

### 8. 时间与金额的展示口径

- 后端一律下发 UTC 的 ISO 8601 时间；前端在 utils/format.ts 中**统一按东八区**格式化展示。
- 金额全程是**字符串**（后端为 decimal(8,2)），展示时只做千分位与两位小数，不做浮点运算。

### 9. 登录态与 401

- 会话令牌存 localStorage，刷新页面后仍可复用（后端会话为 30 分钟滑动过期）。
- 任意接口返回 10002 时：清空本地令牌并**统一跳回登录页**（在 main.ts 注册），登录页给出「登录已超时」提示。
- 修改密码成功后，后端会吊销该账号的**全部会话（含本次）**；前端在 store 的 changePassword 中同步清空并强制重新登录。

### 10. 二次确认的范围

需求把发布、手动冻结、手动下架、进入交易、标记成功、标记失败、修改密码都列为**建议**二次确认项。本项目**全部启用**（一个通用确认弹窗 + 一个交易失败裁决表单）。其中「标记交易成功」的确认文案明确说明连带后果（其余排队买家被标记为失败、商品下架归档、不可撤销）。

### 11. 前后端双重校验

validation/ 按「登录相关 / 发布商品相关 / 意向与交易相关」三部分实现，规则与后端保持一致（长度口径、拒绝尖括号、价格按 BigDecimal 口径解析等）。

但**服务端始终是唯一权威**：前端校验只为体验，后端返回的专属业务码（如 20007、20008、20010、10004、30006、30007）仍会被正确处理。

### 12. DTO 字段保持 snake_case

api/types.ts 中的字段名与后端 JSON **逐字一致**（snake_case），不做驼峰转换，减少一层映射和一处可能的偏差。

### 13. 测试与工具链的环境适配

vitest.config.ts 保持**不 import 任何模块**、并使用 threads 池：Vite 在打包配置阶段会解析外部依赖并调用 child_process，这在受限执行环境中会被拒绝。配置用 process.cwd() 提供 @ 别名，测试因此可以按 @/... 引入模块。

## 六、接口层约定

- 16 个卖家端接口按域拆到 api/session、account、product、intention、history 五个文件，index.ts 统一导出。
- 统一响应形状：{ code, message, data }；其中 data 无值时是 null 且**键仍然存在**。
- 错误码常量集中在 api/types.ts 的 ApiCode；码到界面文案的映射在 constants/messages.ts。
- 令牌由 http.ts 的请求拦截器统一注入 Authorization: Bearer ...。

## 七、测试

目前只有**连通性测试**，文件位于 `src/api/__tests__/connectivity.spec.ts`，用于确认前端能连上后端并正确解析响应外壳：

    npm test

- 默认访问 http://localhost:8080；后端不可达时**自动跳过**并打印提示，不会让测试变红。
- 可用环境变量覆盖：SMOKE_BASE_URL、SMOKE_ACCOUNT、SMOKE_PASSWORD。

## 八、已知偏离与限制

| 项         | 说明                                                               |
| ---------- | ------------------------------------------------------------------ |
| 口令码功能 | 本期前端不做，仅保留后端接口与注释掉的前端定义（见「重要决定 1」） |
| 交易中意向 | 不做独立卡片，按钮放在列表的 trading 行上（见「重要决定 4」）      |
| 首页名单   | 含终态意向，终态行的位次按后端口径照常显示                         |
| 商品编辑   | 卖家端不提供编辑入口（发布后名称 / 描述 / 图片 / 价格不可修改）    |
| 图片上传   | 上传成功但发布失败时会产生孤立文件，系统不做清理                   |
