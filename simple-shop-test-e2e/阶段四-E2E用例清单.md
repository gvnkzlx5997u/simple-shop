# 阶段四 E2E 用例清单（卖家端）

> **本轮只交清单，不写实现**。共 **31 条**：用例按「一条改动 ≥ 1 条」覆盖挑战需求 C 的六件事（§1–§3），外加四条跨页面主流程（§4）。
> 选择器命名沿用现有约定（`data-testid` 用短横线小写），实现时直接照抄。
> 依据：《契约交接》§4（按钮与状态）、§7（E2E 注意事项）；`openapi.json`；卖家端 `src/` 实际实现。

## 0. 前置与数据口径

| 项 | 要求 |
| --- | --- |
| 数据库 | 按 **V4 重建**（收货快照列 NOT NULL 无默认值，订单表必须为空）；E2E 库单独，不复用开发库 |
| 后端环境变量 | `PAYMENT_MOCK_ENABLED=true`、`RATE_LIMIT_ENABLED=false`、`MEDIA_DIR=./target/test-media` |
| 支付 | 四渠道恒成功；要测「支付失败仍待支付」用 `PAYMENT_MOCK_FAIL_CHANNELS=ALIPAY` 重启，不改请求参数 |
| 24 小时超时 | 主流程不等待；要验证就 `update simpleshop_order set create_at = <25 小时前>` 再等一轮扫描（`ORDER_TIMEOUT_SCAN_INTERVAL_MS` 可调小） |
| 会话 | 后端重启后 token 全失效，每个用例组自行登录，不跨重启缓存 |
| 上传目录 | 每轮运行前清 `target/test-media`，否则售后图片跨轮累积 |
| 单号断言 | 订单号/售后号是按日序列，只断言格式（`SO+8位日期+6位`、`AS+8位日期+4位`），不断言具体数字 |
| 造数 | 3 买家 / 4 商品 / 8 订单（七态齐全）/ 2 售后单；可直接复用桌面 `挑战需求C\造数\seed-phase4.mjs` |

## 1. 订单：状态与按钮（对应「改订单列表、删除完成订单」）

| 编号 | 场景 | 前置 | 步骤 | 预期 |
| --- | --- | --- | --- | --- |
| O-01 | 七态筛选 | 七种状态各 ≥1 单 | 依次点 `全部/待支付/已支付/已确认/备货完成/已发货/交易完成/已取消` | 每个 tab 只出现该状态的订单；URL 带 `status=`，刷新后仍停在该 tab |
| O-02 | 列表物流列 | 1 单已发货（多行单号）、1 单未发货 | 看列表「物流」列 | 已发货显示承运商 + 单号**首行**；未发货显示「未发货」；悬停 title 是完整单号 |
| O-03 | **待支付不能确认** | 1 单待支付 | 进详情 | 只有「取消订单」；没有「确认订单」；出现「买家还没付款，这一步要等付款之后才能操作」 |
| O-04 | 已支付可确认 | 1 单已支付 | 点「确认订单」→ 确认 | 状态变「已确认」，进度条推进一格，Toast「订单已确认」 |
| O-05 | 备货完成 → 发货必填 | 1 单备货完成 | 点「开始发货」→ 什么都不选不填，直接提交 | 报错「请选择承运商」「请填写运单号」，弹窗不关闭 |
| O-06 | 发货成功（预设 + 多包裹） | 同 O-05 | 承运商下拉选「顺丰」、运单号填两行 → 提交 | 状态变「已发货」；物流信息里的单号按两行显示；操作区只剩「取消订单」 |
| O-06b | 承运商「其他」 | 另 1 单备货完成 | 下拉选「其他（手动填写）」→ 出现名称框 → 空着提交 → 再填「德邦物流」提交 | 空着提交报「请填写承运商名称」；填好后物流信息显示「德邦物流」（后端只存字符串，不做枚举） |
| O-07 | **已发货没有完成按钮** | 1 单已发货 | 进详情 | 只有「修改物流」与「取消订单」；不存在「交易完成」/「完成订单」 |
| O-08 | 改物流不改状态 | 1 单已发货 | 「修改物流」→ 改单号 → 保存 | 状态仍「已发货」；弹窗回填的是原承运商与原单号；Toast「物流信息已更新」 |
| O-09 | 交易完成只能改物流 | 1 单交易完成 | 进详情 | 无进度条、无「取消订单」；只有「修改物流」 |
| O-10 | 已取消无动作 | 1 单已取消 | 进详情 | 无任何按钮（既不能推进也不能取消） |
| O-11 | 详情售后区块 | 1 单交易完成且有 1 条售后 | 滚到底 | 「该订单的售后」列出单号/标题/状态/结果/退款额；点单号进售后详情；点「在售后管理中查看」带 `?order_no=` |
| O-12 | 退款汇总 | 1 单取消退款 + 1 单售后退款 | 看各自详情 | 「已退款」= 取消退款 + 售后退款之和；无退款时不显示该字段 |

## 2. 售后：列表与处理（对应「新增售后列表与详情」）

| 编号 | 场景 | 前置 | 步骤 | 预期 |
| --- | --- | --- | --- | --- |
| A-01 | 三态筛选 | 待处理/已完成/已取消各 ≥1 | 依次点 `全部/待处理/已完成/已取消` | 只出现对应状态；URL 带 `status=` |
| A-02 | 按订单号搜索 | 已知某订单有售后 | 输入订单号 → 搜索 | 只剩该订单的售后；URL 带 `order_no=` |
| A-03 | 订单号不存在 | — | 输入 `SO00000000000000` → 搜索 | 空态文案「当前筛选下没有售后单…」，不报 404、不白屏 |
| A-04 | 详情展示 | 待处理售后（带 1 张图） | 进详情 | 显示订单号（可点回订单详情）、商品、标题、申请时间；描述按原样换行；图片可点开大图 |
| A-05 | 完成（换货） | 待处理售后 | 「处理并完成」→ 先不选任何结果 | 「确认完成」不可点，出现「请选择处理结果」；三个选项都没有默认选中 |
| A-05b | 完成（换货） | 同 A-05 | 选「换货」→ 确认 | 状态「已完成」+「换货」；**没有**退款金额；提示「换货不产生退款…仍可再申请」；按钮消失 |
| A-06 | 完成（仅退款） | 另一条待处理售后 | 「处理并完成」→ 选「仅退款」→ 确认 | 状态「已完成」+「仅退款」；退款金额 = 订单项单价 × 数量；订单详情「已退款」相应增加 |
| A-07 | 取消/拒绝 | 待处理售后 | 「取消 / 拒绝」→ 确认 | 状态「已取消」；提示「买家可以重新申请…」；按钮消失 |
| A-08 | 已完成不能再取消 | 已完成售后 | 直接访问其详情 | 无动作按钮；后端若被直接调用返回 81002（可选用例） |
| A-09 | 同一订单项重复退款 | 某订单项已有退款类售后完成 | 再对同项申请并「完成（仅退款）」 | 前端 Toast 显示「该订单项已经退过款…」（81004）；售后仍为待处理 |

## 4. 三条主流程（跨页面）

| 编号 | 场景 | 步骤 | 预期 |
| --- | --- | --- | --- |
| M-01 | 支付 → 确认 → 备货 → 发货 | 买家下单并支付 → 卖家确认 → 备货完成 → 发货（填承运商与单号） | 每一步状态按序推进一格，不能跳级；发货后买家端能看到物流（买卖两端一致） |
| M-02 | 收货 → 售后 → 完成退款 | 买家确认收货（成交扣库存）→ 买家按订单项申请售后 → 卖家「处理并完成（退货并退款）」 | 订单「已退款」增加、库存已在收货时扣减、售后状态「已完成」且退款额 = 单价 × 数量 |
| M-03 | 24 小时未支付被系统取消 | 造 1 单待支付 → 把 `create_at` 改为 25 小时前 → 等一轮扫描 | 订单变「已取消」；**不退款、不改库存**（待支付本来没付款也没扣库存） |
| M-04 | 缺货拒绝 → 补货 → 重试 | 买家下单 2 件（库存充足）→ 卖家把该商品库存改为 1（仍 >0，不触发下架）→ 买家确认收货 | 确认收货被拒（60004），订单停在「已发货」、库存不扣；卖家补货到 ≥2 后买家再确认 → 成交、库存按 2 扣减 |
