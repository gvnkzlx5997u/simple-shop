# 买家端 E2E 交接说明（阶段D）

> 面向：后续接手买家端自动化测试的人。
> 对应代码：`simple-shop-buyer-frontend`（阶段D 完成时的状态）。
> 对应后端：`simple-shop-backend`，接口契约见 `simple-shop-doc/阶段三/openapi.json`。

## 1. 已稳定的路径（可以放心写用例）

以下路由与交互在阶段D 全量回归里逐项跑过，选择器与行为都已固定：

| 路由 | 页面 | 关键选择器 | 说明 |
| --- | --- | --- | --- |
| `/goods` | 商品列表 | `.goods-card`、`input[placeholder="搜索商品名称或描述"]`、`button.search-btn` | 每页 12 条；卡片整块可点，没有单独链接 |
| `/goods/:id` | 商品详情 | `button:has-text("加入购物车")`、`button.fav` | `button.fav` 文案在「收藏 / 已收藏」之间切换 |
| `/cart` | 购物车 | `.row-item`、`.row-check`、`.qty-input`、`button.remove`、`.total strong`、`button.checkout`、`button.to-fav`、`.bar .check-all input` | 需登录 |
| `/favorites` | 我的收藏 | `.fav-card`、`button.remove`、`.fav-card.disabled` | 每页 12 条；失效卡片带 `disabled` 类 |
| `/orders` | 我的订单 | `.order-row`、`.filter select`、`button:has-text("下一页")` | 每页 10 条；筛选是**下拉**不是标签页 |
| `/orders/:id` | 订单详情 | `.items tbody tr`、`button:has-text("取消订单")`、`button:has-text("确认取消")`、`button:has-text("再想想")` | 需登录 |
| `/login`、`/register` | 登录、注册 | `input`（按顺序：用户名、密码、…）、`button.primary` | 注册表单 4 个 input：用户名/密码/电话/默认交易地点 |

几条固定行为，可直接作为断言依据：

- **未登录访问 `/cart`、`/favorites`、`/orders`、`/orders/:id`** → 跳 `/login?redirect=<原路径>`。
- **未登录点「加入购物车」或「收藏」** → 同样跳登录，并带回跳地址。
- **下单成功后自动跳 `/orders/:id`**（不是留在购物车弹提示）。
- **取消订单是内联二次确认**：先出「确认取消 / 再想想」，没有 `window.confirm`，不会被浏览器对话框卡住。
- **数量输入框失焦时夹到库存上限**，超过库存会被改回 `stock` 的值。
- **失效行（已下架或库存 0）**：勾选框与数量框都被禁用，行内出现「已下架」或「缺货」。
- **金额**：购物车合计在 `.total strong`，形如 `¥245.50`。

## 2. 现成可跑的脚本

### `d5-full-regression.js`（阶段D 全量回归，44 项）

按《阶段D-买家端开发计划》§9.1 清单逐项走查，分五组：

| 组 | 覆盖 | 项数 |
| --- | --- | --- |
| A | 未登录：列表、详情、搜索（有/无结果）、注册、登录、三个需登录路由被拦、加购跳登录 | 10 |
| B | 购物车：加购、重复加购、数量、夹库存、勾选、全选、刷新恢复、失效行、合计、删除 | 12 |
| C | 下单：单件、多件、含失效行被拦、失败后刷新、库存不足 | 5 |
| D | 订单：列表、分页、倒序、筛选、切筛选回第 1 页、明细二次请求、取消、已发货不可取消 | 10 |
| E | 收藏：收藏、状态回显、列表、失效标注、取消、转收藏、转后可见 | 7 |

跑法（**必须先起后端 8080 与前端 5174**）：

```bash
# Git Bash / WSL
E2E_DB_PASSWORD=<数据库口令> node d5-full-regression.js

# 或直接设成环境变量再跑
set E2E_DB_PASSWORD=<数据库口令>
node d5-full-regression.js
```

可用环境变量：`E2E_BASE_URL`（默认 `http://localhost:5174`）、`E2E_DB_NAME`（默认 `simple_shop_d1`）、
`E2E_DB_PASSWORD`（必填，脚本不落明文）。

结束会打印 `RESULT: ALL CHECKS PASSED` 或 `RESULT: FAILED`，失败时退出码为 1。
脚本**自己会清理**它创建的账号及其订单、购物车、收藏，并把测试商品恢复成初始状态，可重复跑。

### `d3-cart-check.js` + `verify-cart.bat`（购物车 UI ↔ 数据库对账，12 项）

专门核「页面算的钱」和「数据库存的钱」是否一致：改数量、改勾选后逐项查库，
最后比对订单总额、明细之和、页面合计三者。

双击 `verify-cart.bat` 即可（自动检查前后端是否在跑，口令从 `local-config.bat` 取）。

## 3. 测试数据依赖

脚本假定库里存在这些商品（ID 固定，名字参与断言）：

| ID | 名称 | 价格 | 库存 | 状态 |
| --- | --- | --- | --- | --- |
| `GD-D1-ON` | 测试耳机在售 | 199.00 | 5 | 在售 |
| `GD-D1-ON3` | 测试数据线在售 | 15.50 | 3 | 在售 |
| `GD-D1-ON2` | 测试充电线缺货 | 39.90 | **0** | 在售（用来测缺货行） |
| `GD-D1-OFF` | 测试耳机已下架 | 299.00 | 3 | 已下架 |
| `GD-FAV-01..15` | 收藏测试商品1..15 | 11.00~25.00 | 5 | 在售 |

分类固定为 `CL1-D1` / `CL2-D1`（数码 / 耳机）。

**如果要迁到新库**，直接执行同目录的 `simple-shop-d1-fixtures.sql`：

```bash
mysql -uroot -p --default-character-set=utf8mb4 <库名> < simple-shop-d1-fixtures.sql
```

这个文件是**幂等**的：重复执行只会把数据恢复成初始状态（实测把商品改成下架、库存改成 99、
名字改乱之后，跑一次全部复原），不会报主键冲突。

注意：`mysql` 客户端默认字符集不是 utf8mb4，插中文必须加 `--default-character-set=utf8mb4`，
否则报 `ERROR 1366 Incorrect string value`。

另外，商品表有检查约束 `ck_goods_off_shelf`：`status='OFF_SHELF'` 时 `off_shelf_at` 必须非空。
手工改数据时漏了 `off_shelf_at` 会报 `Check constraint ... is violated`。

## 4. 踩过的坑（写用例前先看）

1. **`mysql -e "多行 SQL"` 会只执行第一段**。node 的 `execSync` 走 `cmd.exe` 时把换行当命令分隔符，
   多行 SQL 只跑第一句，报出来的错还很莫名其妙（`Unknown table 'g' in field list`）。
   **传给 mysql 的 SQL 一律写成单行。**
2. **`vite dev` 只监听 `[::1]`**，写 `localhost:5174` 可以，写 `127.0.0.1:5174` 连不上。
3. **本机有系统代理**，命令行 `curl` 要加 `--noproxy "*"`，否则健康检查会被代理拦。
4. **Playwright 用 `channel: 'msedge'`**；`video` 选项在本机不可用。
5. **`simpleshop_queue_sequence` 表不能 TRUNCATE**（id=1 是种子行），缺了会导致提交意向类接口 500。
   阶段D 后买家端已无「意向」接口，但清库时仍要避开这张表。
6. **后端下单不清购物车**。要测「下单后购物车变化」，得看前端有没有删行，别指望后端。
7. **`simple_shop` 开发库可能因 Flyway 校验和过期起不来**，测试请用干净库 + `DB_URL` 覆盖
   （详见买家端 README 的「本地开发」一节）。**不要用 `validate-on-migrate=false` 硬绕**，
   绕过后下一个迁移脚本照样失败（比如要 DROP 一张已不存在的表）。

## 5. 阶段D 后已下线的东西（别照着旧用例写）

- **`/history` 路由与「我的历史」页面**：整页删除，旧路径落到兜底规则重定向到 `/goods`。
- **「我要购买」按钮与购买意向**：`POST /api/buyer/intentions`、`GET /api/buyer/history` 都已从前端移除。
- **「交易中 / 冻结 / 归档」相关文案与分支**：商品只有「在售 / 已下架」两态。
- 阶段一的 36 条用例、阶段二的 57 条用例里，凡是涉及上述功能的都要删掉或重写。

## 6. 还没有自动化的部分

- 真正的并发渲染（两个浏览器同时改同一份购物车）——本地状态是浏览器本地存储，跨标签页不共享。
- 弱网/超时下的加载态与重试（目前只用手动拦截 500 验证过订单详情的「重试」）。
- 图片与媒体文件的展示（测试数据没有真实图片，列表显示「暂无图片」占位）。

## 7. 手动自测怎么起环境（最省事的路径）

**数据库用 `simple_shop_d1`，不要用 `simple_shop`。**
后者是早期版本建的，Flyway 校验和对不上，后端会直接启动失败
（`Validate failed: checksum mismatch`），那不是代码问题。

`simple_shop_d1` 已经建好表、跑过迁移、并有 19 件测试商品，直接连它即可。

### 第 1 步：起后端

在 `simple-shop-backend` 目录下：

```bash
DB_PASSWORD=<你的 MySQL 口令> \
DB_URL="jdbc:mysql://127.0.0.1:3306/simple_shop_d1?useUnicode=true&characterEncoding=UTF-8&connectionCollation=utf8mb4_unicode_ci&connectionTimeZone=UTC&rewriteBatchedStatements=true" \
mvn spring-boot:run -Dspring-boot.run.jvmArguments="-Dserver.port=8080"
```

看到 `Started ... in x seconds` 后，验证一下：
<http://localhost:8080/api/public/health> 应返回 `{"status":"UP"}`。

> 如果 8080 被占用，改成别的端口后前端的 `vite.config.ts` 代理也要跟着改。

### 第 2 步：起前端

另开一个窗口，在 `simple-shop-buyer-frontend` 目录下：

```bash
npm run dev
```

打开 <http://localhost:5174> 即可。

### 第 3 步：按这个顺序点一遍（10 分钟）

1. 不登录，逛列表 → 搜索「耳机」→ 点进详情
2. 详情页点「加入购物车」→ 应跳登录页，登录后回到这件商品
3. 注册一个新账号（用户名/密码/电话/地点）
4. 加购两件 → 进购物车 → 改数量、取消勾选、点全选，看合计跟着变
5. 点「去结算」→ 应跳到订单详情，能看到订单号和明细
6. 订单列表 → 切「已发货」筛选 → 应看到空态和「查看全部订单」
7. 回详情页收藏一件 → 进「收藏」→ 取消收藏
8. 购物车勾选一件 → 点「转收藏」→ 购物车少一行、收藏多一件
9. 刷新页面，确认购物车数量与勾选还在
10. 退出登录 → 确认顶部出现「登录/注册」，购物车、收藏、订单入口消失

### 第 4 步（可选）：跑自动化对账

环境开着的情况下，双击 `verify-cart.bat`，或在命令行执行：

```bash
E2E_DB_PASSWORD=<口令> node d5-full-regression.js
```

最后一行是 `RESULT: ALL CHECKS PASSED` 就说明 44 项全过。
